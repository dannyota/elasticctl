## Live findings and cleanup

Four early Serverless attempts failed contract assertions, including two
runs that added safe diagnostics. All four completed cleanup and baseline
audits. They exposed two fixture assumptions: a hyphenated missing Cases
search shared analyzed terms with the owned case, and the marker
column returned ES|QL type `text`; the fixture expected `keyword`.
The fixes use one unique Cases search term and require the measured marker
type. Product search and projection behavior did not change.

The [Cases API](https://www.elastic.co/docs/api/doc/kibana/operation/operation-findcasesdefaultspace)
defines its search with `simple_query_string` and defaults to OR. The ES|QL
correction retains exact `seq=long` and `marker=text` checks, with a regression
that rejects the old marker type. The corrected commit then passed once on
each flavor without a failed or skipped live test.

Every final run restored the exact original default data view and left no
marker rules, exception lists, indices, data views, dashboards, cases, or
open marker alerts. Custom, prebuilt, and customized rule counts matched
their captured baseline. Closed marker alerts remain under the existing
triage cleanup contract.

Fleet policy inventories and the installed-package inventory matched the
lease's captured baseline after Fleet setup. The lease removed its owned policies
and handled any package it had installed under its cleanup contract.

Lab teardown succeeded. Separate Podman checks by project label and name
found zero lab containers and volumes. The unrelated database stayed running;
Hosted was not stopped.

Raw target output remains in private ignored logs. This document includes
only safe versions, tool names, aggregate results, and cleanup facts.
