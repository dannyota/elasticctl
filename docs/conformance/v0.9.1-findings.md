objects. Every plan's targets were checked against the run's registry before
confirmation, and each change was read back through the API.

The six new kinds ran live on the current protocol path only. Their frames
on both paths are checked offline against the real server binary.

At `9bb36df` the Serverless contract failed three times at the comment
check, each with clean cleanup and baseline. Two of those runs carried local
prints of the failing check's source line, never committed. A case read on
9.7.0 carried no
`comments` array although the comment count had grown, so the check now
reads the comment through `GET /api/cases/{id}/comments/_find`. The same fix
makes the created-rule check require `enabled` equal to `false` in the raw
read, since the model defaults a missing `enabled` to `false`.

## Cleanup and evidence limits

Every create recorded a pending entry before the write. Cleanup removed the
created cases by id and the created rule by exact `rule_id` after it read
back with `enabled: false`, and removed the marker index. Closed marker
alerts are the accepted residue. The lab was destroyed with its job.

- The harness answers the form itself. That is test consent: it proves the
  protocol mechanics, not that a product client asks a person.
- No product client ran for 0.9.1. Model-driven clients run against Hosted
  from 0.9.2 (mutation design D35).
- Raw results and frames stay private. No live request capture is claimed.
