## Corrections from evidence

- None. Task 1 found no runtime defect, all thirteen contracts passed on the
  first matrix run, and the client matrix found no server defect.

## Known limits

- **Claude Code collapses the consent form.** Claude Code 2.1.322 shows the
  action, the target, and the first detail line, then collapses the rest:
  the credential note, the plan id, the hash, and the expiry (M10, as in
  0.9.0). By owner decision neither the code nor D33 changes. Codex CLI shows
  the whole text.
- **Codex CLI cannot send a decline.** Its form offers True or False, so a
  person who refuses ends with `not_confirmed` and no change, and the plan
  stays open until it expires or is discarded. By owner decision this is a
  client behavior, and the result is safe.
- **The scratch live config holds the API key.** `write_live_config` still
  writes `ELASTICCTL_API_KEY` into the run's `config.toml` (mode 0600, in a
  temporary directory). No 0.9.2 task changed it; it stays open for every
  live contract.
- The shared permit check proves the fourth admission by timing. It does not
  gate the release of the held calls. The gap carries over from 0.8.2.
- End-to-end delivery of an expired plan's audit event has no offline test.
  Unit tests cover expiry.

## Evidence limits

- Model-driven clients ran only against the Hosted test deployment (D35),
  once per scenario, at the versions recorded. Raw frames, pane captures, and
  client logs stay private.
- Codex CLI's current protocol path is not measured: version 0.167.1 still
  sends `initialize` with `2025-06-18` when `mcp_2026_07_28` is enabled.
- The harness answer in the mutation contract is test consent. A
  non-interactive client run can only prove refusal.
- No live request capture is claimed.
- Astra's reviews were static. CI ran the full suite on each merged head.
