# elasticctl 0.9.3 review record

0.9.3 is a cleanup patch. It closes three limits that the 0.8.2 to 0.9.2
reviews carried forward and changes no tool, schema, limit, error code,
consent rule, or CLI output. The one runtime change is a hidden test seam.
Each code slice had an independent review on a different model before it
joined `dev-0.9.3`: Sol implemented and Astra reviewed. Astra's sandbox could
not run Cargo, so its reviews were static; the integrator reran the gates on
each change. See the [findings](../conformance/v0.9.3/findings.md) for the
matrix.

| Slice | Verdicts | What the fixes covered |
| --- | --- | --- |
| Plan (#121) | Prose, no separate review | None |
| Code scanning triage (Task 1) | No code change | Eleven open `rust/hard-coded-cryptographic-value` alerts were test ownership markers passed to a parameter named `nonce`. All were dismissed as false positives with the reason used for the sixty earlier ones; none is open |
| Live config without the API key (Task 3, #123) | MERGE | None. The config the live harness writes has no `api_key`; each child gets the key only through its environment. Mutation-contract children resolve as `Flags`, but every visible target string still uses the profile name |
| Test-only plan life and the expiry audit (Task 2, #124) | MERGE, no findings | None. Astra checked 2,701 minute boundaries: with the seam unset, the consent text and every projection match 0.9.2 |
| Gated permit check (Task 4, #125) | MERGE-WITH-FIXES, then MERGE | The gate's HTTP forwarding ran on the test runtime, so a descheduled test thread could stall a request past a server deadline. It now runs on its own thread and runtime |
| Research rows (Task 6) | Static check by Sol at `v0.8.2` | Ten of the eleven 0.8 guarantees hold with code and test evidence; the eleventh holds for content (an SDK schema cache shares allocations) |

## Closed limits

- **The scratch live config held the API key** (open since 0.9.0). Closed by
  #123.
- **The shared permit check proved the fourth admission by timing** (open
  since 0.8.2). Closed by #125.
- **No test drove a plan's expiry through the server** (0.9.2 evidence
  limit). Closed by #124.

## Known limits

- **Claude Code collapses the consent form** after its first three lines,
  the credential note included (M10). An owner decision in 0.9.2 keeps the
  code and D33 unchanged.
- **Codex CLI cannot send a decline.** A person who refuses ends with
  `not_confirmed` and no change, and the plan stays open until it expires or
  is discarded. A client behavior, by the same owner decision.
- **The plan-life seam is reachable from Rust.** `TestOptions` and the test
  entry point are public but hidden from the documentation. Neither the CLI,
  MCP, nor `ServerOptions` can set it.

## Evidence limits

- The reviews were static. CI ran the full suite on each merged head.
- No live request capture is claimed.
