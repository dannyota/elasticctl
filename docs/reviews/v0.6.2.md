# v0.6.2 development review

The review covers integration-policy read consistency and Fleet conformance.
Selector, controller, and Fleet lifecycle reviews are complete. Whole-branch
review and three-flavor measurement remain pending.

| Finding | Resolution |
| --- | --- |
| A selected integration could change identity or summary before its exact read | Check the requested id and compare the fetched summary with the selected list row before get or export returns it. |
| Fleet setup could retry after an ambiguous failure | Send setup through the one-shot transport and verify one request on a retryable failure. |
| Setup failure could leave a prior successful report | Clear the target report before setup. |
| The setup-order regression did not exercise production startup | Test the initializer that clears the report, validates setup, and captures the initial baseline. |
| Paging regressions could fail at an unmatched URL | Use the full production routes and assert requests, error class, short pages, duplicate ids, and stable totals. |
| Package cleanup checked only marker policies | Read all integration policies and refuse every system-package consumer before uninstall. |
| Failed cleanup could discard the mutation-attempt state | Keep lease transitions in the guard so later cleanup observes an ambiguous mutation without replaying it. |
| Bootstrap inputs could broaden ownership before validation | Retain the intended identity, validate an exact read and production nonsecret export, and adopt only the materialized inputs. |
| Required ownership fields could inherit portable defaults | Require live identity and safety fields before normalization; retain the recorder's absent/null rules for optional environment fields. |
| The install-response check assumed a version field | Validate the pinned asset-list schema, then prove the exact version through package status and inventory. |
| CLI checks accepted incomplete report evidence | Require structured conflict errors, applied overwrite reports, and exact ids, actions, counts, and export contents. |
| Cleanup failure cases lacked request-level regressions | Prove zero deletes for inventory/version drift and pre-attempt foreign installs; prove ambiguous bootstrap recovery sends one create and one delete. |
