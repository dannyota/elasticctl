## Recorded results

- **Pooling with one attempt (Task 1).** With the pool on, a write after the
  server closed the previous socket either fails as a connection error after
  one request or opens a new connection, and a dropped write is never
  replayed. The write transport turns the pool off anyway, so the guarantee
  does not rest on the dependency's retry behavior.
- **Elicitation API (Task 1).** With the new `rmcp` features, a throwaway
  `cargo check` confirmed that `Peer::create_elicitation_with_timeout`,
  `CallToolResponse::InputRequired`, `InputRequest::Elicitation`,
  `ElicitationSchema::builder`, and `RequestContext::protocol_version`
  resolve. `Cargo.lock` gained only `dependencies` entries, with no new
  package.

## Corrections from live evidence

- **Hosted "no change" check (#84).** The contract compared full rule reads.
  After child B enabled the marker rule, Kibana rewrote `execution_summary` on
  Hosted 9.5.6, and the contract failed twice with clean cleanup. It now
  compares `normalize::canonical`, the form drift detection uses.
- **Consent text layout (#85, D33).** Claude Code 2.1.322 shows only the first
  three lines of a form message. The first layout hid the action and every
  affected object. The text now opens with the action, the target, and the
  first object, and `plan_declined` says the plan is closed, because a model
  told the person a declined plan was still open.
- **Key note (#86, #87, D34).** M13 could not run until the lab check read the
  cluster UUID from Kibana stats and each rule was enabled by its creator
  first. It then showed that a rule keeps the API key it has. The note, the
  README, and the wiki now say so.
- **Harness bug found by the integrator (#80).** A raw test responder
  advertised keep-alive while closing each socket, which failed pooled reads
  before the write. The responder was fixed; the transport was correct.

## Known limits

- **The scratch live config holds the API key.** `write_live_config` writes
  `ELASTICCTL_API_KEY` into the run's `config.toml` (mode 0600, in a temporary
  directory). Astra asked for a secret-free config with the key passed through
  the child environment. Deferred to 0.9.2; it applies to every live contract.
- **Cleanup before 0.9.0 could fall back to a display name.** Live-contract
  cleanup deleted rules through the CLI selector, which resolves a display name
  when no rule has the id. A contract that had already deleted its marker rule
  could then delete another rule whose name equals that id. 0.9.0 deletes by
  exact `rule_id`, counts a 404 as cleaned, and tests a name equal to a deleted
  id. Live runs of 0.8.x code keep the exposure.
- **`doctor` warns with a stale reason for an organization-level key.** Its
  `key_scope` warning says enabling a rule will fail. Serverless 9.7.0 accepts
  such a key for an enable (shared design 7.2), so the reason is wrong there,
  though the warning still points to the supported credential. 0.9.0 keeps
  CLI output byte-identical apart from three named changes, so the fix waits
  for 0.9.1, spec first.
