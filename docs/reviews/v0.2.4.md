# elasticctl 0.2.4 Review

A static review of the post-0.2.3 codebase validated seven defects and one
policy decision. Each defect has a failing regression before its fix, and every
fix is isolated to its boundary. No issue is reserved for a later 0.2 release.

| # | Finding | Source | Impact | Regression test | Fix |
| --- | --- | --- | --- | --- | --- |
| 1 | Config saves truncated in place and followed symlinks | `elasticctl-core/src/config.rs` `Config::save` | A pre-existing loose-permission file kept its inode; a symlinked config wrote through to its target | `save_atomically_replaces_a_permissive_existing_file`, `save_replaces_a_symlink_without_writing_its_target` | `Replace config files atomically` |
| 2 | Environment values read lossily; URL userinfo not scrubbed at every sink | `elasticctl-core/src/config.rs`, `transport.rs`; `elasticctl-cli/src/context.rs`, `cmd/config_cmd.rs` | A non-integer `ELASTICCTL_TIMEOUT` was silently dropped, and a direct `Profile` with URL userinfo leaked through `redacted`, `host`, `save`, and `--debug` | `config_init_rejects_an_invalid_environment_timeout_without_writing`, `debug_output_never_shows_url_userinfo` | `Check configuration input boundaries` |
| 3 | Malformed bulk and import responses read as "nothing happened" | `elasticctl-api/src/rules.rs` `bulk_by_rule_ids`, `ops.rs`, `rules_ops.rs`, `exceptions.rs` | A contradictory or missing summary reported zero success, silently dropping a partial mutation | `bulk_outcome_rejects_malformed_success_bodies`, `malformed_import_response_is_rejected` | `Reject malformed mutation outcomes` |
| 4 | Malformed export trailer, preview, and identity responses tolerated | `elasticctl-api/src/codec.rs`, `rules.rs`, `health.rs` | A recognized but mistyped export trailer was discarded, and a malformed preview or identity body read as zero or "unknown" | `a_recognized_malformed_trailer_is_not_discarded`, `decode_preview_hits_checked_rejects_malformed_bodies`, `doctor_reports_a_malformed_identity_as_failed` | `Reject malformed read responses` |
| 5 | Mirror reads followed symlinks and ignored directory read errors | `elasticctl-api/src/state/mirror.rs` | A symlinked `rules/` directory or rule file escaped the mirror, and a lost directory entry was skipped | `read_mirror_refuses_a_symlinked_rules_directory`, `read_mirror_refuses_a_symlinked_rule_file` | `Refuse incomplete mirror reads` |
| 6 | Pull journal accepted illegal phase jumps | `elasticctl-api/src/state/transaction.rs` | A corrupt journal could roll back a target on a phase the transaction never reached | `recovery_rejects_an_illegal_phase_jump_without_removing_a_target` | `Validate pull journal transitions` |
| 7 | Package-content gate omitted `elasticctl-core` | `scripts/check-packages.sh`, `elasticctl-core/Cargo.toml` | The core crate packaged its integration tests | `scripts/check-packages.sh` core gate | `Inspect every published crate` |

## Reviewed with no change

The transport retry policy was reviewed and left unchanged. `elasticctl-core`
retries 429 and 5xx with backoff and never retries 4xx, matching the design
contract in `elasticctl-design.md` §3.1 and the transport tests that pin each
behavior (`a_429_is_retried_and_then_succeeds`, `a_400_is_never_retried`). No
review finding justified changing it.

## Outcome

The final search found no issue reserved for v0.2.5. All seven defects are
fixed in v0.2.4 with regression coverage, and the release proceeds to package,
CI, live, and publish gates.
