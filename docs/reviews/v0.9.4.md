# elasticctl 0.9.4 review record

0.9.4 makes a 0.9 binary refuse a state mirror written by 0.10, the owner's
decision D21 in the 0.10 value lists design. It changes nothing for a mirror
without `value-lists/`, apart from the error a mirror that cannot be inspected
now reports.

| Slice | Verdicts | What the fixes covered |
| --- | --- | --- |
| Plan and shared design 5.6 (#132) | Prose, reviewed with the code | `state pull` joined the refusal, because pulling into a 0.10 mirror would leave its value lists stale for a later 0.10 push |
| The guard (#132) | MERGE-WITH-FIXES, then MERGE | Before review, the integrator changed the check so that only a missing entry passes and any other metadata error fails closed. Sol asked for a regression of that branch and for its error in the plan and spec; a Unix case makes the mirror unsearchable, asserts the error, zero requests, and no file change, and fails on a fail-open version |

Terra implemented and Sol reviewed. Sol's sandbox could not run Cargo, so its
reviews were static; the integrator reran the tests on each change.
