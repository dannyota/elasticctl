# v0.7.0 development review

The seven-tool stdio MCP server passed independent implementation, safety,
packaging and whole-branch review. All confirmed findings are closed.
The [live evidence](../conformance/v0.7.0-findings.md) proves every tool on
Serverless 9.6.0, Hosted 9.5.2 and self-managed 9.5.1, plus all seven calls
through MCP Inspector 2.5.0 on the lab. Cleanup and lab teardown passed.
Final evidence and documentation review passed.

## Review corrections

| Finding | Resolution |
| --- | --- |
| The first current request could block cancellation during startup | Replay it into the SDK concurrent request loop and check protocol metadata on each request. |
| Aborting the SDK waiter could detach the session | Cancel I/O and await the bounded SDK drain before runtime shutdown. |
| SDK tasks could log remote text through an outer subscriber | Run each session on a dedicated runtime thread under a local no-op subscriber. |
| Doubled-scheme rejection missed mixed-case input | Normalize the scheme check while retaining the supplied base path. |
| Legacy output schemas need an object root | Declare an object root with typed success and failure alternatives. |
| Schema and redaction tests could miss the active field or error envelope | Follow schema references and inspect representative structured and text results with excluded sentinels. |
| Nine catalog text fields omitted their input bounds | Add exact descriptions and character constraints while retaining runtime UTF-8 byte validation. |
| Python JSON decoding accepted nonstandard numeric constants | Reject NaN and infinities before accepting ownership evidence. |
| Oversized input ending in bare carriage return reached clean EOF | Check the buffered size at EOF and return the existing static size error. |
| The harness test did not prove bounded consumption | Count consumed bytes and require rejection before the sentinel tail is read. |
| Fallible reader startup could leave a child alive | Own the child before thread setup and reap it before returning. |
| A reader panic could skip the second join | Join both readers before returning a static error. |
| Catalog checks could accept another page | Reject every present non-null continuation cursor. |
| Pending interruption could start a later mutation or preserve passing evidence | Check each leg and mutation boundary, finish exact cleanup, and invalidate late summaries. |

Each behavior correction has a regression that failed against the prior
behavior or an explicit negative control. Schema/projection coverage includes
actual route allowlists, unknown fields, stable identity, nullability,
paging, byte limits, and safe errors. Independent re-review approved each
corrected slice before integration or live execution.

## Boundaries

The first CLI test cycle included two ordinary selectors without an explicit
config path. They could have read the default config; target access was not
established. Later config-dependent child tests use temporary configs. The
live run used explicit private configs and runtime credentials throughout.

Unexpected harness panics use exact cleanup through the guard but cannot
prove the final baseline. Such a run fails. The private runner handles
ordinary INT, TERM and HUP; SIGKILL or host loss still requires recovery and
new evidence. Neither limit was encountered in this passing run.

Versions remain 0.6.2 during development. No release or publication ran.
First publication of the MCP crate still needs the separate owner decision
specified in [releasing.md](../releasing.md). Ownership checks do not prove
Trusted Publisher settings, and workspace registry uploads are not atomic.
