# 0.9 MCP mutation research

Research date: 2026-11-10. Baseline: `f7c9fe5`, workspace version 0.7.4.
This is planning evidence. No 0.9 code exists. The
[0.8 design](../specs/elasticctl-mcp-tasks-design.md) was written at the same
time; its section 13 and this design's section 10 state the agreement between
the two.

## Recommendation

Add mutation to the MCP server as two calls: a typed planner that only reads,
and one `plan_apply` tool that takes a plan id and nothing else. A plan is
applied only after a person answers a server-written confirmation form in the
client. The form travels on the elicitation channel, which tool arguments
cannot write to. A client without form elicitation cannot apply through MCP.
The operator enables mutation classes at startup; the default stays read-only.

The [design](../specs/elasticctl-mcp-mutation-design.md) holds the decisions.
This file holds the evidence and the open measurements.

All pages are the 2026-07-28 revision on modelcontextprotocol.io, read
2026-11-10.

| Evidence | Source | Consequence |

| `inputResponses` and `requestState` are request parameters beside `arguments`, not inside it. | [Tools, input required results](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#input-required-tool-results) | A model fills `arguments`. | "servers **MUST** treat `requestState` as an attacker-controlled input." Integrity protection "**MAY** be omitted only when tampering can cause nothing worse than request failure." No HMAC key is needed. |
| "Servers **MUST NOT** send an `inputRequests` that the client has not declared support for." Clients declare `elicitation: {form: {}, url: {}}` per request in `_meta`; an empty object means form only. | [MRTR requirement 7](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr#server-requirements-basic-workflow), [Elicitation capabilities](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation#capabilities) | Check the form capability on every `plan_apply`. | Form mode schemas are flat objects of primitives. Clients "SHOULD pre-populate form fields" with defaults. | URL mode is for "interactions that must *not* pass through the MCP client", such as credentials and OAuth. | Clients "**MUST**" show which server is asking and offer decline and cancel. Clients "**SHOULD** implement user approval controls". Nothing forbids a client from answering without a person. | [Elicitation security considerations](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation#security-considerations) | The server cannot prove a person answered. | "there **SHOULD** always be a human in the loop with the ability to deny tool invocations." Clients "**SHOULD**" prompt "for user confirmation on sensitive operations". | [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#user-interaction-model) | Client approval is a SHOULD. It is defense in depth, not the consent. |
| `ToolAnnotations` are hints. Defaults: `readOnlyHint` false, `destructiveHint` true, `idempotentHint` false, `openWorldHint` true. `destructiveHint` false means "only additive updates". Clients "**MUST** consider tool annotations to be untrusted unless they come from trusted servers." | [Schema, ToolAnnotations](https://modelcontextprotocol.io/specification/2026-07-28/schema#toolannotations), [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#tool) | Set honest annotations so clients that use them prompt. Enforce nothing through them. |
| The tool list "**MUST NOT** vary per-connection or as a side effect of other requests". | [Tools, capabilities](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#capabilities) | Mutation tools appear from a startup flag only. No tool unlocks another. |
| State across calls uses "an explicit handle" with enough entropy, a bounded lifetime stated in the tool description, and an expiry error. Servers "**SHOULD** use secure, non-deterministic handles". | [Tools, stateful tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#stateful-tools), [Security best practices, state handle hijacking](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices#state-handle-hijacking) | `plan_id` is a random handle with a 15-minute life and a `plan_expired` error. stdio has one client, so the process is the principal. |
| On stdio a client cancels with `notifications/cancelled`. "Servers **MAY** ignore cancellation notifications if ... The request cannot be cancelled". | [Cancellation](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation) | A write that has been sent runs to its response. Cancellation before the write stops the call. |
| Tasks left the core protocol for the `io.modelcontextprotocol/tasks` extension. The extension overview lists approval gates as a use. The client matrix shows no client with Tasks support. | [Changelog item 6](https://modelcontextprotocol.io/specification/2026-07-28/changelog), [Tasks overview](https://modelcontextprotocol.io/extensions/tasks/overview), [client matrix](https://modelcontextprotocol.io/extensions/client-matrix) | Every 0.9 apply is one write inside the call deadline. Tasks are not used. |
| The security best practices page covers OAuth proxies, token passthrough, SSRF, state handles, and local server installs. It has no rule for confirming a tool's mutation. | [Security best practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices) | The human-in-the-loop SHOULD on the tools page is the only confirmation guidance. |

## Owner decisions, 2026-11-10

`rules-toggle` ships first, with the credential note. Exception items and
rule update stay out of 0.9. Plans require a reachable Elasticsearch URL, and
the error names `es_url`. Two prompts per apply in Claude Code are accepted.
An audit trail on stderr only is accepted. The key for M9 is pending.

The bounded `rules_list` page (`rules_ops::list_page`) ships in 0.7.5, not in
0.8.0. 0.9 does not call it; the 0.9 live and client runs need a server at or
after 0.7.5 so `rules_list` can find marker rules on the trial stacks.
