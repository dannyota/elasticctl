# elasticctl 0.8.1 MCP Resources and Prompts Implementation Plan

**Goal:** Add five listed resources, four resource templates, and four
static prompts to the 0.8.0 server, and prove them on three flavors.

**Architecture:** A resource is a fixed-argument call of an existing tool
adapter, run through the same admission, deadline, and cancellation helper
as `tools/call`. A prompt is validated arguments in a fixed text, with no
I/O. No new read path, projection, limit, dependency, or SDK feature.

**Tech Stack:** Rust 2024 / Rust 1.97.1, rmcp 3.9.0, Tokio, serde/schemars,
wiremock, assert_cmd, jsonschema, the 0.8.0 fixtures.

**Spec:** [0.8 design](../specs/elasticctl-mcp-tasks-design.md), sections 3,
8, 9, 10, 12, and 13; [0.8.0 plan](v0.8.0.md) for shared interfaces.

Status: planned on 2026-11-10 and revised the same day after independent
review. Starts from the released 0.8.0 tag. Release and publication need
separate approval. `resources/list` reads nothing from Elastic (owner
decision, 2026-11-10).

## Global Constraints

- Use `rmcp = "=3.9.0"`, `default-features = false`, with `server`, `macros`, and `transport-io`. Add no feature and no dependency.
- Capabilities are exactly `{"prompts": {}, "resources": {}, "tools": {}}`. No `listChanged`, `subscribe`, `completions`, or extension.
- `resources/list`, `resources/templates/list`, `prompts/list`, and `prompts/get` send no Elastic request, need no credential, and hold no call permit.
- `resources/read` holds one of the four call permits and obeys the whole-call deadline and cancellation. Its text is at most 262,144 bytes and its frame at most 1,048,576 bytes.
- The resource tables are the compile-time constants of design sections 8.2 and 8.3. A read can reach only those nine tool calls. No URI is fetched, normalized, or built from remote text.
- Resource text is byte-identical to the matching tool call's text content.
- Prompt arguments follow the grammars of design section 9.1. Prompt text is the literal of design section 9.3.
- Outbound protocol errors keep one sanitizer. It allows only the five messages and the one `data` shape of design section 10.3.
- The 24 and 26 name tool catalogs, every tool schema, and every tool result are unchanged from 0.8.0. CLI snapshots stay byte-identical.
- Each Rust file stays at or under 700 non-test lines. Comments use plain words with no history wording.
- The three-flavor matrix is a release gate for 0.8.1, exactly as for 0.8.0. It is not waived, narrowed, or replaced by 0.8.0 evidence.
- Local builds use two jobs, tests use four threads, one build-heavy process at a time.
- Keep development versions at the released 0.8.0 value; release preparation performs the bump.

## Task 1A: URI parser and resource tables

**Interfaces:**

```rust
// src/resources/uri.rs
#[derive(Clone, Debug, PartialEq, Eq)]
pub(crate) enum ResourceRef {
    CoverageTactic, CoverageTechnique, Doctor, Info, PrebuiltRulesStatus,
    Alert { alert_id: String },
    Case { case_id: String },
    ExceptionList { namespace_type: String, list_id: String },
    Rule { rule_id: String },
}
pub(crate) const MAX_URI_BYTES: usize = 4_096;
pub(crate) fn parse(uri: &str) -> Option<ResourceRef>;

// src/resources/mod.rs
pub(crate) struct ResourceCall {
    pub tool: ToolId,
    pub arguments: rmcp::model::JsonObject,
    pub expect_rule_id: Option<String>,
}
pub(crate) fn call_for(reference: &ResourceRef) -> ResourceCall;
pub(crate) fn list() -> Vec<rmcp::model::Resource>;
pub(crate) fn templates() -> Vec<rmcp::model::ResourceTemplate>;
```

Write the percent decoder by hand in `uri.rs`: two hex digits after `%`,
either case; anything else fails. Do not use `url::Url` to parse the URI,
because it normalizes paths and case.

- [ ] Add red unit tests in `uri.rs` for every rule of design section 8.1: the nine valid shapes; `%2F`, `%20`, and multibyte ids decode once and round-trip; `%25` yields a literal `%` and is not decoded again; rejected: wrong scheme, uppercase scheme, authority other than `stack`, `plans` authority, empty segment, trailing slash, `?`, `#`, `@`, `%zz`, a lone `%`, invalid UTF-8 after decoding, a 1,025-byte id, a whitespace-only id, U+0000 and U+007F, `.` and `..` segments, an extra segment, a missing segment, `namespace_type` other than `single` or `agnostic`, and a 4,097-byte URI.
- [ ] Add red unit tests in `mod.rs`: `list()` and `templates()` equal literal expectations for URI, `name`, `title`, `mimeType`, and order; each `description` equals the matching tool's description from `catalog::definitions()`; no entry has `size`, `icons`, or `annotations`; `call_for` returns the tool and arguments of the design tables for all nine shapes, with `expect_rule_id` set only for `Rule`.
- [ ] Run `cargo test --locked -p elasticctl-mcp --lib resources --jobs 2 -- --test-threads=4`; record the expected failures. Implement. Run green with Clippy and the length gate. Obtain review.

## Task 1C: Shared admission helper and error allowances

**Interfaces:**

```rust
// src/server/admission.rs
pub(super) enum Admitted<T> { Done(T), Busy, DeadlineExceeded, Cancelled }
pub(super) async fn run_admitted<T, F>(
    state: &std::sync::Arc<ServerState>,
    cancellation: tokio_util::sync::CancellationToken,
    operation: F,
) -> Admitted<T>
where F: std::future::Future<Output = T>;

// src/result.rs
pub(crate) fn text_of(result: &rmcp::model::CallToolResult) -> Option<&str>;
```

`run_admitted` holds the try-acquire, the deadline, the cancellation select,
and the permit release that `call_tool` holds today. `call_tool` keeps its
exact results: `busy`, `deadline_exceeded`, the cancelled protocol error, and
the late-completion check after the deadline.

- [ ] Before any change, run MCP `--lib` and every MCP integration test and keep the output as the baseline.
- [ ] Move the admission code into `run_admitted` with identical tokens where possible. `call_tool` maps `Admitted` back to its current results. The synthetic test tools and their controls keep working unchanged.
- [ ] Add unit tests for `run_admitted` alone: fifth concurrent operation is `Busy` and runs nothing; a slow operation is `DeadlineExceeded`; a cancelled token is `Cancelled` and drops the future; the permit is free after each outcome.
- [ ] Extend `sanitize_protocol_error` per design section 10.3. Add unit tests: each of the five messages survives; any other message is replaced by code as before; code `-32002` gets `MCP resource not found` when its message is not allowed; a `data` object with exactly `kind`, `http_status`, `code` and legal values survives; `data` with an extra key, a `message` key, an unknown `kind`, an unknown `code`, a string `http_status`, or status 99 or 600 is removed; a sentinel inside a removed `data` never reaches the output.
- [ ] Rerun the baseline commands; every earlier test passes unchanged. Run Clippy and the length gate. Obtain review that compares tool-path behavior before and after.

## Task 2: Wire resources and prompts into the handler

**Files:** MCP `src/server/handler.rs`; create `tests/resource_protocol.rs`
and `tests/prompt_protocol.rs`; modify `tests/stdio_protocol.rs` and
`tests/support/mod.rs`.

Handler behavior, all in `impl ServerHandler for McpServer`:

- `get_info`: capabilities built with resources and prompts enabled and no
  list-changed or subscribe flag; instructions unchanged.
- `list_resources`, `list_resource_templates`, `list_prompts`: a request with
  a cursor returns `ErrorData::invalid_params("Invalid cursor", None)`;
  otherwise the tables, with no `next_cursor`.
- `read_resource`: `uri::parse`; on `None` return
  `ErrorData::resource_not_found("Resource not found", None)`. Otherwise
  `call_for`, then inside `run_admitted` call
  `tools::adapter_for(tool).call(tool, Some(&arguments), &state, ct)` and
  build the tool result with the same `project_success` function
  `call_tool` uses. For `expect_rule_id`, compare with
  `data.rule_id` of the result and treat a mismatch as not found. Return
  `ReadResourceResult` with one
  `ResourceContents::text(text, request_uri).with_mime_type("application/json")`.
- `read_resource` errors follow the table of design section 8.5. Core
  `not_found` maps to the not-found helper. Every other failure is
  `ErrorData::new(ErrorCode::INTERNAL_ERROR, "Resource read failed", Some(data))`
  where `data` is `{kind, http_status, code}` from `error::core` or
  `error::local`. `AdapterError::InvalidArgument` cannot occur for a parsed
  URI; map it to not found.
- `get_prompt`: `prompts::render`; map `UnknownPrompt` to
  `invalid_params("Unknown prompt", None)` and `InvalidArguments` to
  `invalid_params("Invalid prompt arguments", None)`.
- `complete`: return the method-not-found error.

- [ ] Add red tests in `resource_protocol.rs` over `serve_io`, on the current path and the legacy path: capabilities object exact; both lists exact and ordered, with `ttlMs: 0`, `cacheScope: "private"`, and `resultType: "complete"` only on the current path; a cursor is `-32602` `Invalid cursor`; lists send zero Elastic requests and work with no credential.
- [ ] Add red read tests with wiremock bodies from recorded fixtures: for each of the nine shapes, `contents[0].text` equals `content[0].text` of the matching `tools/call`, `uri` echoes the request, and `mimeType` is `application/json`; an id with `%2F` reaches the adapter decoded.
- [ ] Add red error tests: unknown URI, bad grammar, Elastic 404, and a rule found by name but with another `rule_id` are `-32602` on the current path and `-32002` on the legacy path, message `Resource not found`, no `data`; a 403 is `-32603` with `data` `{"kind":"permission","http_status":403,"code":"elastic_permission"}`; four held reads make a fifth `busy`, and a held read makes a fifth tool call `busy`; a one-second deadline is `deadline_exceeded`; a rule body above the structured cap is `result_too_large`; a cancelled read sends no response and frees its permit; no error holds the URI or a remote sentinel.
- [ ] Add red tests in `prompt_protocol.rs` on both paths: list exact; each prompt's text equals the literal; every rejection of Task 1B is `-32602` with the right static message and no `data`; `prompts/get` sends zero Elastic requests and succeeds while four tool calls are held.
- [ ] Add red tests: `completion/complete` is `-32601`; `subscriptions/listen`, `resources/subscribe`, `tasks/get`, and `skills/list` stay refused; the tool catalog and one tool result are unchanged from 0.8.0.
- [ ] Replace the 0.7 regression in `stdio_protocol.rs` that expects resources and prompts to be unavailable with the new exact-capability assertion. Add `EXPECTED_RESOURCE_URIS`, `EXPECTED_TEMPLATE_URIS`, and `EXPECTED_PROMPT_NAMES` literals to `tests/support/mod.rs`.
- [ ] Run both new targets red; implement; remove the `dead_code` attributes of Tasks 1A and 1B; run the whole MCP test suite, Clippy, and the length gate. Obtain adversarial review of the read path and the error mapping.
