# elasticctl 0.5.1 Dashboards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete typed dashboard administration and portable transfer, plus explicit opaque Saved Objects bundles for dependency-inclusive migration.

**Architecture:** Build on 0.5.0's `content_codec` and data-view vertical. `-core` gains a named-filename multipart helper; `-api` gains low-level typed dashboard and Saved Objects wrappers plus dashboard orchestration; `-cli` gains `dashboards` and `dashboards bundle`. Typed JSON/YAML is primary. Saved Objects NDJSON remains byte-for-byte opaque.

**Tech Stack:** Rust 2024 (stable), tokio + reqwest multipart, serde/serde_json/serde_yaml_ng, clap, wiremock + assert_cmd + tempfile, xtask fixture recorder.

**Spec:** [`docs/specs/elasticctl-content-design.md`](../specs/elasticctl-content-design.md) sections 1-4 and 6-15. Shared contracts are in [`docs/specs/elasticctl-design.md`](../specs/elasticctl-design.md).

## Global Constraints

- Dependency direction is exactly `elasticctl-cli -> elasticctl-api -> elasticctl-core`; orchestration and content models do not enter `-core`.
- Dashboard identity is `id`. Exact title is selector fallback only and duplicate exact titles are a conflict naming their ids.
- Every dashboard route requires `Feature::Dashboards`, whose verified floor is Kibana 9.5.1.
- Typed artifacts are JSON arrays by default and YAML sequences on request. Each `DashboardSpec` is `{id,data}`; `data.title` is a required non-empty string.
- `data` remains an ordered JSON map so new GA fields survive. `meta` and GET warnings never enter the artifact.
- Warning-bearing typed export refuses and directs the operator to bundle export.
- Typed import rejects `time_range.mode` before mutation and audits every successful PUT response with recursive subset comparison. Accepted-but-dropped state is `applied: true`, `lossy: true`, exit 1.
- Import conflict behavior is default-refuse, `--overwrite`, or `--skip-existing`; the two flags conflict.
- A typed dashboard file retains referenced ids. Missing `data_view_reference.ref_id` values are refused before the guard.
- Bundle export sends explicit dashboard ids with `includeReferencesDeep: true`. Bundle bytes are emitted unchanged.
- Bundle import scans line metadata without rewriting attributes or migration fields; apply uploads the exact pre-guard bytes.
- Every import and delete previews by default and applies only with `--yes`, printing profile, host, and space.
- Multi-object typed imports continue after per-object failures and loss; no rollback. Bundle import follows the server's all-resolvable-errors contract.
- Fixtures are recorded live and marker-scoped. No unscoped dashboard list or Saved Objects export may enter public fixtures.
- Commit messages are plain imperative sentences with no prefixes, agent attribution, trailers, or generated-by text.
- Gates: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -- --test-threads=6`, `cargo deny check advisories bans licenses sources`, `./scripts/check-packages.sh`, `./scripts/check-fixtures.sh`.
- The workspace version stays `0.5.0`; the release flow performs the version bump.

```rust
async fn named_multipart_uses_the_requested_filename() {
    let server = MockServer::start().await;
    Mock::given(method("POST"))
        .and(path("/api/saved_objects/_import"))
        .respond_with(ResponseTemplate::new(200).set_body_json(json!({
            "success": true, "successCount": 1, "successResults": [], "errors": []
        })))
        .expect(1)
        .mount(&server)
        .await;
    let t = Transport::new(&profile_for(&server)).unwrap();
    t.post_multipart_ndjson_named(
        "/api/saved_objects/_import?overwrite=false",
        "dashboards.ndjson",
        "{\"type\":\"dashboard\",\"id\":\"d1\"}\n",
    ).await.expect("upload");
    let requests = server.received_requests().await.unwrap();
    let request = &requests[0];
    let body = String::from_utf8_lossy(&request.body);
    assert!(body.contains("filename=\"dashboards.ndjson\""));
    assert!(body.contains("\"id\":\"d1\""));
    assert_eq!(request.headers.get("kbn-xsrf").unwrap(), "true");
    assert_eq!(request.headers.get("elastic-api-version").unwrap(), "2023-10-31");
}
```
