# v0.2.0 final review fixes

## Purpose

Close the five defects found by the final whole-range review before v0.2.0 is
released. The fixes must fail closed around remote deletion and recorded
identity, preserve the existing command model, and keep the release at three
published crates.

## Mirror item validation

Every top-level exception item decoded from a rule or export bundle must have
a readable non-empty string `item_id` and `list_id`. An omitted
`namespace_type` keeps the existing `single` default, but a present value must
be a non-empty string. Mirror reading rejects an invalid item before any
remote reconciliation.

Item grouping returns `Result` and propagates identity errors. It must never
skip an item. This provides defense in depth if another decoder constructs an
invalid item later. A regression test supplies a malformed top-level item for
a container with remote items and proves planning fails with no writes or
deletes.

## Fixture authority scrubbing

The recorder treats every configured recording authority as sensitive data.
Matching is ASCII case-insensitive. Exact configured authorities are scrubbed
wherever they occur. For HTTP port 80 and HTTPS port 443, including
zero-padded forms, the corresponding bare host is also scrubbed. Non-default
ports do not create a bare-host alias.

Matches use authority-safe boundaries so a configured host is not replaced
inside a longer hostname. The scrubber handles URLs separated by commas,
semicolons, quotes, brackets, or whitespace and removes userinfo from every
URL. Tests cover each delimiter, mixed casing, normalized default ports,
userinfo, and the existing non-default and plain-`@` exclusions.

## Strict rule find envelopes

Rule `_find` responses must be JSON objects containing array `data`, unsigned
integer `total`, positive integer `page`, and positive integer `per_page`.
The decoder rejects missing or mistyped fields, `data.len() > total`, and
`data.len() > per_page`, rather than converting malformed responses to an
empty result.

All callers share this decoder. Source-partition verification and prebuilt
customized counts therefore fail on API drift. Tests exercise malformed fields
through both call paths and assert that no dependent action is reported as a
valid empty result.

## Pull lock paths

Pull lock derivation uses an absolute lexical form of the requested mirror
path. This makes `--dir .` and other relative paths derive a stable sibling
lock while leaving the caller-visible path unchanged.

A filesystem root has no safe sibling and is refused with an explicit error.
Tests cover the current-directory form and platform root behavior. Windows CI
continues to run the focused state transaction suite.

## Published packages

`elasticctl-api-test-support` remains private and unpublished. The API and CLI
package manifests exclude their integration-test trees, whose only purpose is
workspace validation and whose imports cannot resolve after Cargo removes the
path-only private dev-dependency.

Package verification must show no retained integration tests in the API and
CLI tarballs, then build all three publishable crates through the existing
workspace dry run. Runtime source, unit tests, documentation, and license files
remain packaged.

## Verification

Each behavioral fix follows red-green testing: first reproduce the reported
failure, then apply the smallest production change and rerun the focused
suite. Final verification includes formatting, locked workspace clippy and
tests, Cargo deny, fixture scanning, package file inspection, three-crate
publish dry run, distribution build and checksums, the Windows-focused tests
where locally runnable, and all six live conformance tests.

No tag, push, registry upload, or release is part of these fixes.
