# v0.2.0 final review fixes

## Purpose

Close the five defects found by the final whole-range review before v0.2.0 is
released. The fixes must fail closed around remote deletion and recorded
identity, preserve the existing command model, and keep the release at three
published crates.

## Mirror item validation

Every top-level exception item decoded from a rule or export bundle must have
readable, non-empty string `item_id` and `list_id` values. An omitted
`namespace_type` keeps the existing `single` default, but a present value must
be a non-empty string. Unknown non-empty namespace strings remain accepted so
the decoder can carry future server values without mapping them to `single`.

This stronger check is contextual. `ExceptionItem::from_value` continues to
accept a nested item with no `list_id`, because `split_items` assigns the
authoritative parent container identity. Both NDJSON bundle items and YAML
top-level items pass through a top-level validator before entering `Mirror`.
Mirror reading therefore rejects invalid top-level identity before any remote
reconciliation.

Item grouping returns `Result` and validates `item_id`, `list_id`, and any
present `namespace_type` instead of skipping an item. This provides defense in
depth if another decoder constructs an invalid item later. One state test
supplies a malformed top-level item for a container with remote items and must
first fail because the current planner succeeds with an item removal. After
the fix it must return an error naming `list_id`, perform no item-reconciliation
read, and issue no `POST`, `PUT`, or `DELETE`. A direct grouping test constructs
an invalid transparent item and proves the defense-in-depth error path.

## Fixture authority scrubbing

The recorder treats every configured recording authority as sensitive data.
Matching is ASCII case-insensitive. Exact configured authorities are scrubbed
wherever they occur. For HTTP port 80 and HTTPS port 443, including
zero-padded forms, the corresponding bare host is also scrubbed. Non-default
ports do not create a bare-host alias.

Matches use authority-safe boundaries so a configured host is not replaced
inside a longer hostname. Exact-authority matching applies to plain strings as
well as URL authorities. URL scanning treats commas, semicolons, quotes,
parentheses, angle brackets, square brackets outside an IPv6 literal, and
whitespace as token boundaries. A bracket-aware scan consumes a complete IPv6
literal and optional port before treating `]` as a trailing delimiter. It
removes userinfo from every URL token.

A table-driven test covers every delimiter, mixed casing, HTTP and HTTPS
default ports, zero-padded `:0080` and `:0443`, userinfo on each URL, bracketed
IPv6, and whitespace-separated multiple URLs. Each target is paired with a
preserved decoy: longer and prefixed hostnames, a bare host configured with a
non-default port, and plain `ops@example.com` text.

## Strict rule find envelopes

Rule `_find` responses must be JSON objects containing array `data`, unsigned
integer `total`, positive integer `page`, and positive integer `perPage`, which
is the spelling in every recorded rule response. Exception-list `_find`
continues to require its distinct `per_page` field. Unknown fields are
accepted; the rule decoder does not accept both page-size spellings without a
separately measured compatibility requirement.

The decoder rejects missing or mistyped fields, `data.len() > total`, and
`data.len() > perPage`, rather than converting malformed responses to an empty
result. Errors use `ErrorKind::Http` and name the rule `_find` endpoint and the
bad field or count relationship.

All callers share this decoder. Source-partition verification and prebuilt
customized counts therefore fail on API drift. Direct tests cover every
missing or mistyped required field, zero page values, oversized data, numeric
overflow, and unknown-field acceptance. Caller tests feed an otherwise valid
prebuilt status followed by a malformed customized response, and an empty
source result followed by a malformed partition response. Both must return the
typed error instead of a `PrebuiltStatus` or empty rule report.

## Pull lock paths

Pull resolves the requested mirror path to one filesystem identity before lock
or transaction work. If the mirror exists, the complete path is canonicalized.
If it does not, the nearest existing ancestor is canonicalized and normal
remaining components are appended; an unresolved `..` suffix is refused
instead of being normalized across a possible symlink. The resolved path is
used for the sibling lock and every transaction filesystem operation. The
original spelling remains available only for user-facing output and errors.

The sibling lock is `.<mirror-name>.elasticctl-pull.lock`. A filesystem root
has no safe sibling and is refused with `ErrorKind::Error` and a message
containing `filesystem root has no safe sibling lock`. This includes Unix `/`,
Windows drive roots, and UNC share roots.

Tests prove `.` and its absolute equivalent conflict on the same held lock;
`./`, an existing `dir/..`, and a supported symlink alias resolve to the same
identity; a missing mirror under a symlinked existing parent uses the same
lock; root errors match the required message; and user-facing output preserves
the requested spelling. Platform-specific root and symlink cases run under
the appropriate `cfg`.

## Published packages

`elasticctl-api-test-support` remains private and unpublished. Add
`exclude = ["tests/**"]` to the `elasticctl-api` and `elasticctl` package
manifests. This removes their complete integration-test trees, whose imports
cannot resolve after Cargo removes the path-only private dev-dependency.
Inline unit tests under `src/` remain packaged.

Add `scripts/check-packages.sh` and run it in CI. For each API and CLI package,
it inspects `cargo package --list --locked --allow-dirty` and rejects every
`tests/` entry or `elasticctl-api-test-support` source. It also requires
`Cargo.toml`, `Cargo.toml.orig`, `Cargo.lock`, and the crate's `src/` entrypoint.
Repository-root README and license files are distributed by cargo-dist and are
not claimed as members of the individual `.crate` archives. After the content
check, the existing locked three-crate publish dry run must still pass.

## Verification

Each behavioral fix follows red-green testing: first reproduce the reported
failure with the assertions above, then apply the smallest production change
and rerun the focused suite. Final verification includes formatting, locked
workspace clippy and tests, Cargo deny, fixture scanning, the package-content
script, three-crate publish dry run, distribution build, and checksums.

The Windows CI job runs these exact locked commands, and the new lock tests
must execute rather than filter out:

```text
cargo test --locked -p elasticctl-api --test state
cargo test --locked -p elasticctl-api transaction
cargo test --locked -p elasticctl --bin elasticctl report_file
```

The live command must report six passed and zero failed for these six named
tests: pull/diff cleanliness, rule export/import round trip, stale-pointer
repair, doctor health, exception bundle round trip, and source defaults with
selected prebuilt rules. An exit-zero run that filters them out is not proof.

No tag, push, registry upload, or release is part of these fixes.
