# 0.1.1 backlog

Items deferred out of the 0.1.0 reviews. None threatens data, credentials, or
the mutation-safety contracts; each was judged not worth blocking the release.

## Behaviour

1. `rules export --json` without `--out` emits raw NDJSON, not a JSON
   document. Deliberate for 0.1.0 (blank CSV/table output was worse), but it
   is the one place `--json` does not produce parseable JSON. Decide: document
   it as the export contract, or emit `{"ndjson": "..."}` there. Add a test
   either way.
2. `--debug` logs nothing before a request is sent and nothing on the timeout
   or connection-error branches — the cases an operator most reaches `--debug`
   for. Add a pre-send line or a `-> connection error` line on the `Err` arms
   of `Transport::send`.
3. `Profile` URLs are not validated for userinfo, so `https://user:pass@host`
   in a config would surface in the guard banner and the `--debug` line. No
   URL the client builds today carries credentials; a `strip_userinfo` at
   config load closes the class.
4. `state pull` aborts on the first filename collision instead of collecting
   all collisions; a second colliding pair stays hidden until a re-run.
5. `Rule::from_value` accepts a `rule_id` key without requiring it to be a
   string; four call sites each cope independently (list, validate,
   `Drift::compute`, `sort_rules`). Decide once whether `from_value` should
   require a string, rather than ever patching a fifth site.

## Tests

6. The capability tests use `"default"` as the self-managed `build_flavor`
   stand-in; a real 9.5.1 stack reports `"traditional"`
   (`tests/fixtures/traditional-9.5.1/status.json` is the recorded proof).
   Behaviour is safe — only `"serverless"` is matched exactly — but one
   wiremock case should use the recorded literal.
7. The completion test is a smoke test: it would pass if the wrong shell's
   script were emitted. Pin one shell-specific token per shell.

## Process, first release only

8. Tag `v0.1.0-rc.1` before `v0.1.0`: the cross-platform release matrix (musl,
   macOS, Windows) has never run, and a discardable prerelease is the only way
   to exercise it and the release workflow end to end.
9. Fire one manual `workflow_dispatch` of the CI `live` job after pushing:
   `podman compose` provider resolution on `ubuntu-latest` is unproven.

## Cleanup

11. `docs/plans/v0.1.0.md` still carries 16 stale `--package elasticctl-cli`

## From the real-data evaluation, 2026-08-13

Three read/write exercises against a live Serverless project holding 2,066
prebuilt rules (all seven rule types), plus a 40-rule Sigma-converted custom
corpus and 1.7 MB of ingested Mordor events. Full reports under
`.superpowers/eval/`. The state loop held: zero drift on the untouched
corpus, byte-identical double pull, exact export round-trip for every type,
and the push touched nothing outside its two edited rules.

13. **`rules preview` reports no hit count** — the highest-value improvement
    found. A rule with 4 hits and a rule with 0 hits render byte-for-byte
    identically; the only hit signal is the `max_signals` warning at 100+.
    The API's `preview_id` is printed but there is no way to fetch its
    results. A detection engineer iterating on a rule still needs an external
    `_count`, which defeats the command. Fetch and render the preview alerts
    (count at minimum, sample hits ideally).
14. `rules export` cannot select a subset: exporting "my 40 rules" means
    exporting all 2,106 and filtering the NDJSON by hand. Support selectors
    (rule_id list, tag) on export.
15. Re-importing an existing corpus is a 409 storm — 40 "already exists"
    errors and exit 1 — rather than an idempotent skip, and the client-side
    dry run cannot warn about conflicts it has not asked the server about.
    Add a skip-existing mode; consider the server-side `dry_run` for import.
16. `rules get` of an unknown id falls back to a full-corpus name search:
    ~8.8 s at N=2,066 to say "not found". Cap or page the fallback, or make
    it opt-in.
17. `doctor` prints the API key id unredacted in its auth check. Not the
    secret half, but identifying; truncate it.
18. `info` hardcodes `license_tier: null` and does not list spaces — correct
    on Serverless only by coincidence. Probe them.
19. Commit a small `samples/` harness from the verified eval commands
    (`.superpowers/eval/data-sources.md`): fetch-don't-vendor scripts for a
    Sigma slice (sigma-cli, `lucene` + `ecs_windows` + `siem_rule_ndjson`)
    and the three MIT Mordor datasets, with the ECS remap and
    timestamp-rewrite step preview needs. EVTX-ATTACK-SAMPLES is excluded:
    no license.
