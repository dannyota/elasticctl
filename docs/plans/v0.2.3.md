# elasticctl 0.2.3 Cross-Flavor Conformance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one safe conformance runner, exercise the six existing 0.2 live contracts on Serverless, Hosted, and self-managed 9.5.1, and release scrubbed evidence as 0.2.3 without changing product behavior.

**Architecture:** A new xtask module probes one target, captures its baseline, invokes each existing ignored live test as an exact serialized subprocess, and writes a deterministic public report only after cleanup is proved. The live harness emits machine-readable failure classes while raw detail stays in ignored private logs. Cloud targets come from .env; the 9.5.1 lab remains ephemeral.

**Tech Stack:** Rust 1.97.1, Cargo, elasticctl-core, elasticctl-api, serde_json, Bash, jq, Podman Compose, GitHub Actions, cargo-dist, GitHub CLI.

## Global Constraints

- 0.2.3 changes conformance tooling, tests, reports, documentation, and release metadata only. Do not change CLI, API, transport, or output behavior.
- Run the same six contracts on serverless, ech, and traditional through cargo xtask conformance.
- The verified compatibility floor is Kibana 9.5.1. A skip names its unsupported feature and that floor.
- Every identity is registered before mutation. Runs are serialized and refuse completion while marked objects remain or rule partitions drift.
- Never print, commit, or report a real URL, deployment or account identifier, credential, location, user identity, live object content, or raw failure.
- Keep subprocess output under target/conformance-private/ only.
- Do not persist the ephemeral lab key. Destroy lab volumes after the run.
- Ordinary contract failures are valid 0.2.3 evidence when cleanup succeeds. Cleanup, harness, or baseline failures invalidate the run.
- Do not re-record fixtures unless an exchange or target version changed.
- GitHub Release ends the release. Do not publish 0.2.3 to crates.io without separate approval naming 0.2.3.
- Work sequentially on local master; do not use workers or a worktree.

- docs/specs/elasticctl-design.md: normative conformance rules.

- crates/elasticctl-cli/tests/live.rs: failure classification and contracts.

- scripts/check-conformance-reports.sh: schema and leak gate.
- .github/workflows/ci.yml: invoke the report gate.
- docs/conformance/v0.2.3/: three reports and findings.
- docs/plans/v0.2.x-release-ladder-design.md: next-release decision.
- Cargo.toml, Cargo.lock, CHANGELOG.md, and the info snapshot: metadata.

fn conformance_marker(class: ConformanceFailureClass) -> &'static str {

- [ ] **Step 4: Implement the run loop**

1. Parse args and build a transport from generic environment variables.
2. Probe capabilities and reject a label mismatch.
3. Capture a marker-clean baseline.
4. Check mapped feature floors; record an explicit unsupported skip.
5. Run the exact test and write both streams to its ignored private log.
6. Record pass on success; record fail and continue only for contract.
7. Invalidate the run for cleanup or harness.
8. Audit markers and partitions after each attempted contract.
9. Write <flavor>-<version>.json with a final newline after final audit.

Derive the root from env!("CARGO_MANIFEST_DIR"). Console output is limited to flavor, version, contract, and result.

report even when a row records an ordinary contract failure.
