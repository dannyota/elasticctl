# v0.2.4 Review Fixes Design

## Purpose

v0.2.4 closes every issue validated by the post-v0.2.3 code review. It is the
next crates.io release only after the review has no known issue that would
otherwise require an immediate v0.2.5.

## Release rule

- Fix every reproducible correctness, safety, or release issue found in the
  current review in v0.2.4.
- Do not create a speculative v0.2.5 backlog from this review.
- Do not broaden the patch for unproven concerns or unrelated refactoring.
- Publish v0.2.4 to GitHub and crates.io only after local, CI, package, and live
  verification pass.

## Validated scope

### Atomic private config replacement

`Config::save` currently truncates the destination before the replacement is
complete. On Unix, an existing permissive file also keeps its old mode while
the new credentials are written, until a later chmod.

Write the serialized config to a private temporary file in the destination
directory. Sync it, atomically replace the destination, then sync the directory
where the platform supports it. The destination must be mode `0600` on Unix.
An interrupted pre-commit write must preserve the previous config. Replacing a
symlink must not overwrite its target.

### Checked configuration boundaries

The CLI currently ignores invalid or non-Unicode `ELASTICCTL_*` values. An
ignored target override can leave the saved profile as the effective target,
and an invalid timeout silently uses another value. Add a checked environment
loader and use it at both CLI call sites. Keep the existing public loader for
source compatibility.

URL userinfo is stripped during normal CLI resolution, but public helpers and
direct `Transport` construction can still retain or print it. Strip userinfo
when saving, redacting, deriving a host, and constructing a transport. These
boundaries must be safe even when a caller constructs `Profile` directly.

### Strict mutation outcome decoding

The bulk rule and rule/exception import paths currently replace absent or
wrongly typed response fields with zero counts or empty errors. A malformed
successful HTTP response can therefore produce a successful command report
whose outcome is unknown.

Require the measured summary fields at the API boundary. A malformed 2xx body
must return an `Http` error. Valid responses retain the current public report
types and rendered fields. Empty local import plans still return the existing
zero report without making a request.

### Fail-closed mirror enumeration

The mirror reader uses iterator flattening over `read_dir`, which discards
individual directory-entry errors. `state diff` or `state push` can then treat
an unread file as absent and make a destructive decision from an incomplete
mirror.

Propagate each entry error with the mirror directory in the message. Do not
follow a symlinked `rules` or `exceptions` directory, or a recognized mirror
file that is a symlink. Continue to ignore readable files and directories with
unrecognized extensions.

### Strict rule-export trailer decoding

The bundle decoder currently discards a trailer when its recognized fields
cannot be deserialized. A scoped export can then omit its missing-object report
and exit successfully.

Reject a recognized but malformed trailer with its NDJSON line number. Keep
the existing compatibility defaults for fields absent from valid historical
trailers.

### Strict preview and identity decoding

Preview-hit search currently turns a malformed successful response into zero
hits. Keep the existing public tolerant decoder for source compatibility, add
a checked decoder, and route live preview reads through it. A malformed hit
envelope must become `hits_error`, which preserves the preview report while
refusing a false zero.

The doctor identity probe currently reports `unknown` fields as successful
authentication. Require a string username and authentication-realm type so a
malformed 2xx response makes the auth check fail.

### Pull-journal transition validation

The pull journal validates its prepared manifest but accepts arbitrary phase
updates. Recovery can therefore interpret corrupt state as proof that a new
target belongs to the interrupted transaction. Require each entry to advance
through `Prepared`, `BackingUp`, `BackedUp`, `Installing`, and `Installed` in
order. Preserve the journal and target when a complete record is invalid.

### Complete package-content coverage

The package-content gate currently inspects the API and CLI crates but omits
`elasticctl-core`. The core package therefore includes its integration tests
and can change package contents without failing the gate.

Exclude core integration tests from its published package and make the package
script inspect all three publishable crates. Keep each crate's manifest,
lockfile, and entry point required.

## Reviewed with no change

The shared transport intentionally retries responses carrying HTTP 429 or 5xx
status, including multipart requests. The existing specification and tests
make this a public contract. Timeouts, connection failures, and response-body
failures are not retried because their mutation outcome is ambiguous. Keep this
policy unchanged in v0.2.4.

## Compatibility

- Keep the public Rust API source-compatible for this patch release.
- Keep valid CLI JSON and human-readable output unchanged.
- Keep config paths, profile resolution, and relative `--config` paths working.
- Keep valid historical NDJSON bundles readable.
- Add no deployment-specific URLs, credentials, identifiers, or raw live data.

## Verification

Each fix starts with a regression test that fails against v0.2.3. Run focused
tests after each change, then the repository format, lint, test, dependency,
package-content, and release preflight gates. Re-run the applicable live
contracts against the trial Serverless, hosted, and self-managed test targets.
Inspect packaged crates before publishing them in dependency order.
