# elasticctl 0.4.2 Conformance and Review-Patch Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the 0.4 capability area: the eighth live conformance contract (triage), the cross-flavor matrix run with committed reports, and the bounded review patch for defects found by a static review of the shipped 0.4 code.

**Architecture:** The triage contract is a live `#[ignore]` test in `crates/elasticctl-cli/tests/live.rs` driving the shipped `-api` functions, registered in `xtask/src/conformance.rs`'s `CONTRACTS`. Baseline machinery gains asymmetric triage awareness in both layers: open `elasticctl-live-*` marker alerts and `elasticctl-live-marker`-tagged cases must be zero; residual *closed* marker alerts are tolerated by not counting them (triage spec section 9's accepted deviation). The review patch fixes controller-supplied findings, each with a regression test.

**Tech Stack:** Rust 2024, existing live-test harness (`live.rs` idioms), xtask conformance/matrix, podman lab, jq-based report gate.

**Spec:** [`docs/specs/elasticctl-triage-design.md`](../specs/elasticctl-triage-design.md) sections 9–11; [`docs/specs/elasticctl-design.md`](../specs/elasticctl-design.md) section 8.3 (cross-flavor conformance). Interface ground truth for the harness: the conformance reference the controller supplies with each dispatch.

## Global Constraints

- Dependency direction `cli → api → core`; `live.rs` cannot import anything from `xtask` — harness logic needed in both places is written natively in each, keyed to the `elasticctl-live-` marker family (`LIVE_PREFIX`, `LIVE_TAG`), never the recorder's `elasticctl-sample` family.
- The triage contract follows `live.rs`'s existing skeleton exactly: `skip_unless_live()`, `serialize_live()`, `write_live_config`/`live_profile`, baseline capture before any mutation, cleanup registration BEFORE the mutation that creates each object, one closure body returning `TestResult`, then `conclude(result, &mut cleanup, baseline)`. Failures classify through the existing `panic_conformance` markers (`elasticctl-conformance-class:contract|cleanup`).
- Asymmetric residue rule (spec section 9): open marker alerts → 0, marker cases → 0, closed marker alerts tolerated. Alert markers are detected by `kibana.alert.rule.rule_id` prefix `elasticctl-live-` (rule ids are `unique_name(...)`-generated, so prefix matching is the stable key); case markers by the `elasticctl-live-marker` tag.
- Every remote mutation the contract performs targets explicit ids or an `elasticctl-live-*`-scoped query; nothing touches untagged objects. The dev Serverless project's prebuilt corpus is read-only ground truth.
- The contract must pass on all three flavors. Assignment coverage: the traditional lab activates a user profile during matrix boot (reusing the recorder's internal-login machinery inside xtask); the contract itself resolves profiles per flavor and exercises assign/unassign with the first activated profile, failing the contract if none exists — all three legs are expected to have one after boot.
- `CONTRACTS` grows 7 → 8 (`name: "triage"`, `features: &[]` — every supported stack serves the triage routes); the array-pinning unit test updates with it; `scripts/check-conformance-reports.sh` gains the 8-contract `v0.4` family list. A missing edit there fails the gate closed.
- Review-patch scope is bounded: exactly the findings file the controller supplies at dispatch; each fix carries a regression test; nothing else changes. A finding the implementer believes wrong is reported back, not silently skipped.
- Spec updates land in the same commit as the change they describe: triage spec section 9's contract sketch is rewritten to the implemented form (including the profile-activation refinement of "resolve the operator's own username"), and main spec section 8.3 is checked for contract enumerations and updated if it names them.
- Matrix reports commit under `docs/conformance/v0.4.2/` (three `<flavor>-<version>.json` + `findings.md` following the prior directories' shape); a run's report is written only when the leg ends clean — read report JSON for truth, not exit codes.
- Live rules: credentials only from the main checkout's `.env`, values never printed (presence checks and name-greps only); never stop/suspend the Hosted deployment; suspended Serverless → resume and retry; lab last, torn down after.
- Commit messages: plain imperative; never mention AI/agents; no trailers.
- Gates: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -- --test-threads=6`, `./scripts/check-packages.sh`, `./scripts/check-fixtures.sh`, plus `./scripts/check-conformance-reports.sh` once reports exist.
- Workspace version stays `0.4.1`; the release flow bumps it.

### Task 1: The triage live contract in live.rs

**Files:**
- Modify: `crates/elasticctl-cli/tests/live.rs` only.

**Interfaces:**
- Consumes: every existing `live.rs` helper (section 1 of the conformance reference); `elasticctl_api::{alerts, alerts_ops, cases, cases_ops, profiles, rules}` public functions (reference section 6); `elasticctl_core::Transport`.
- Produces: the `#[ignore]` test `triage_transitions_alerts_and_cases_and_leaves_only_closed_residue` (Task 2 registers this exact name); `LiveCleanup::{case, alert_rule}` registration methods with matching cleanup in `clean()`; `LiveBaseline` triage fields and `assert_clean_baseline` checks.

- [ ] **Step 1: Extend `LiveCleanup` and `LiveBaseline` with offline unit tests first**

`LiveCleanup` gains two tracked sets and their cleanup:

```rust
    cases: BTreeSet<String>,        // case ids to delete (tolerate an already-deleted 404)
    alert_rules: BTreeSet<String>,  // rule_ids whose alerts must be closed by marker-scoped query
```

- `fn case(&mut self, case_id: impl Into<String>)` and `fn alert_rule(&mut self, rule_id: impl Into<String>)`, mirroring `rule()`/`list()`.
- `clean()` ordering: close alerts for every tracked `alert_rule` FIRST (a query-scoped `alerts::status_by_query` on `{"term": {"kibana.alert.rule.rule_id": <id>}}` with `Conflicts::Proceed`, then a verify that no OPEN alert remains for that rule, retried 3×1s like `retry`), then delete tracked cases (`cases::delete`, treating `NotFound` as already-clean), then the existing rule/list/index deletions. Closing before rule deletion mirrors the recorder's proven disable-then-close ordering; register the rule in BOTH `rules` (delete) and `alert_rules` (close) so cleanup disables the source before sweeping.
- The existing `Drop` fallback and `retry` helper apply unchanged.

`LiveBaseline`/`assert_clean_baseline` gain the asymmetric checks (write the pure decision function separately so it unit-tests offline):

```rust
/// Open `elasticctl-live-*` marker alerts and `elasticctl-live-marker` cases
/// must be zero at baseline and after cleanup. Closed marker alerts are
/// tolerated: alerts have no delete API, so a closed residue row is inert
/// (triage spec section 9).
fn triage_residue_is_clean(open_marker_alerts: u64, marker_cases: u64) -> bool {
    open_marker_alerts == 0 && marker_cases == 0
}
```

Counting helpers (async, driven like `search_probe`'s transport usage):
- open marker alerts: `alerts::search` with body `{"query": {"bool": {"filter": [{"prefix": {"kibana.alert.rule.rule_id": "elasticctl-live-"}}], "must_not": [{"term": {"kibana.alert.workflow_status": "closed"}}]}}, "size": 0, "track_total_hits": true}`, reading `total`.
- marker cases: `cases::find_page` with `cases_ops::find_query(&CaseFilter { tag: Some(LIVE_TAG.into()), ..Default::default() }, 1, 1)`, reading the returned total.

Offline unit tests (in `live.rs`'s existing `#[cfg(test)]`-style non-ignored tests if present, else as plain tests beside the helpers): `triage_residue_is_clean` truth table (0/0 clean; open>0 dirty; cases>0 dirty; closed-only residue is simply not an input — document why in a comment), and a `LiveCleanup::for_test()`-based check that `case`/`alert_rule` register and `tracks`-style inspection sees them.

Run: `cargo test -p elasticctl --test live -- --skip ignored` (or the file's existing offline-test invocation) — RED then GREEN for the new unit tests.

- [ ] **Step 2: Write the `triage_probe` helper and the contract test**

Constants: `const TRIAGE_POLL_ATTEMPTS: u32 = 30;` `const TRIAGE_POLL_INTERVAL: Duration = Duration::from_secs(10);` (~5-minute alert budget, the recorder's proven cadence).

`triage_probe(profile, index, rule_id, cleanup) -> TestResult` — own `tokio::runtime::Runtime` + `Transport::new(&profile)`, like `search_probe`. Steps, each asserting its outcome:

1. Create `index`, seed 3 documents with `@timestamp` now and a marker field, refresh (mirror `search_probe`'s seeding).
2. Create the marker rule enabled via `elasticctl_api::rules::create`: `rule_id`, name = the same string, tag `LIVE_TAG`, type `query` over `index`, query matching the marker field, `interval "1m"`, `from "now-10m"`. (`cleanup.rule(...)` and `cleanup.alert_rule(...)` were registered before the call.)
3. Poll for an OPEN alert of this rule: `alerts::search` on `{"bool": {"filter": [{"term": {"kibana.alert.rule.rule_id": rule_id}}], "must_not": [{"term": {"kibana.alert.workflow_status": "closed"}}]}}` with `alerts_ops::default_sort()` and `alerts_ops::RESOLVE_SOURCE_FIELDS`, up to `TRIAGE_POLL_ATTEMPTS`; fail the contract with a clear message on timeout. Keep the first hit's id.
4. By-id transitions through the shipped plan/apply pairs: `plan_status_by_ids`/`apply_status_by_ids` to `Acknowledged` (assert report `updated == 1`, `failed == 0`), then to `Closed` (same asserts).
5. Query-scoped transitions: `plan_status_by_query` on the rule_id term (assert `matched >= 1`, the preview details are non-empty, and the advisory line is present as the last detail), `apply_status_by_query` to `Open` then again to `Closed` with `Conflicts::Abort` (assert `failed == 0` both times).
6. Tags: `plan_tags`/`apply_tags` add then remove `"elasticctl-live-triage-check"` on the alert id (assert `updated == 1` each way).
7. Profiles + assignment: `capabilities` flavor from the transport; `profiles::suggest(t, flavor, "")`; assert the call succeeds (this exercises the per-flavor route switch, including the Serverless internal route). Take the first activated profile — the matrix boots every leg with at least one (Task 3 activates the lab's) — and `alerts::set_assignees` add then remove its uid on the alert (assert `updated == 1` each way). Fail the contract with a message naming the missing-profile cause if the list is empty.
8. Cases round trip through the shipped pairs: `plan_create`/`apply_create` (title `unique_name("case")`, tag `LIVE_TAG`; register `cleanup.case(id)` immediately from the apply result's `id`), `plan_attach`/`apply_attach` of the (closed) alert id (assert `updated == 1`), `plan_comment`/`apply_comment`, `plan_status`/`apply_status` to `Closed` (assert `updated == 1`), then `plan_delete`/`apply_delete` (assert `updated == 1`) and verify `cases::get` now returns `NotFound`.
9. Final sweep: `alerts::status_by_query` close on the rule_id term with `Conflicts::Proceed`, then assert zero OPEN alerts remain for the rule (poll up to 5×3s — the disable happens at rule deletion in cleanup, so one straggler execution may race; the sweep-and-recheck absorbs it).

The test itself is the standard skeleton (skip guard, `serialize_live`, tempdir, config+profile, `capture_baseline`, `unique_name`s, cleanup registrations, closure, `conclude`). `#[ignore = "requires a live stack"]`, name exactly `triage_transitions_alerts_and_cases_and_leaves_only_closed_residue`.
