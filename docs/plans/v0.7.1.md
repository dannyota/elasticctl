# elasticctl 0.7.1 MCP Read Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend MCP inspection across triage, content, Fleet, and operator-enabled
synchronous search.

**Architecture:** Add vertical adapters to the reviewed 0.7.0 library. Reuse
its target, schema, error, transport, cancellation, and output boundaries.
Each serial worker includes its catalog wiring in the reviewed slice.

**Tech Stack:** Rust 2024 / Rust 1.97.1, rmcp 3.2.0, Tokio, serde/schemars,
wiremock, assert_cmd, recorded fixtures.

**Spec:** [MCP design](../specs/elasticctl-mcp-design.md), especially sections

Status: execution started on 2026-09-06 after owner approval. The 0.7.0
reviews and gates are complete. Release and publication remain separate.

## Global Constraints

- No `clap` type enters the MCP library, API, or core.
- Use `rmcp = "=3.2.0"`, `default-features = false`, with `server`, `macros`, and `transport-io`.
- Input line: 262,144 bytes; structured content: 262,144 bytes; complete outbound frame: 1,048,576 bytes; upstream body: 16,777,216 decoded bytes.
- List limits default to 50 and accept integers 1-200. There is no domain result cursor in 0.7.
- Each selector/filter string must contain non-whitespace text and be at most 1,024 UTF-8 bytes. Use the shared validators and prove rejection before I/O for every field. The ES\|QL query has its separate 65,536-byte cap.
- Four active calls; the fifth returns `busy` immediately. Whole-call timeout defaults to 30 seconds, range 1-120. Shutdown grace is five seconds.
- The 0.7.1 catalog has twenty tools by default and twenty-two when queries are enabled at startup.
- No tool accepts target, credential, local file, arbitrary HTTP, debug, or mutation options. Query opt-in is immutable for the process.
- Existing API feature floors, identity checks, source defaults, and CLI behavior remain unchanged.
- Local builds use two jobs, tests use four threads, and only one build-heavy process runs at a time.
- Keep development versions at the released 0.7.0 value; release preparation performs the coordinated bump.
