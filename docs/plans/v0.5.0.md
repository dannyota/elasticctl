# elasticctl 0.5.0 Data Views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete data-view administration and portable transfer with stable ids, guarded import/default changes, and reference-safe deletion.

**Architecture:** Keep `elasticctl-cli -> elasticctl-api -> elasticctl-core`. `-api` gains a portable JSON/YAML codec, low-level data-view route wrappers, and data-view orchestration; `-cli` gains the `data-views` command group and guard adapters. The existing search resolver moves onto the shared data-view selector without changing search output. `-core` is unchanged.

**Tech Stack:** Rust 2024 (stable), tokio + reqwest, serde/serde_json/serde_yaml_ng, clap, wiremock + assert_cmd + tempfile, xtask fixture recorder.

**Spec:** [`docs/specs/elasticctl-content-design.md`](../specs/elasticctl-content-design.md) sections 1-5, 8-14. Shared contracts are in [`docs/specs/elasticctl-design.md`](../specs/elasticctl-design.md).

## Global Constraints

- Dependency direction is exactly `elasticctl-cli -> elasticctl-api -> elasticctl-core`; `clap` types never enter `-api` or `-core`.
- Data-view identity is the stored `id`. Exact `name` is selector fallback only; zero matches is `not_found`, multiple matches is `conflict`.
- Portable files are JSON arrays by default and YAML sequences on request. The same `DataViewSpec` values must round-trip through both.
- Portable specs require non-empty `id` and `title`, reject unknown top-level keys, strip `version` and `namespaces`, and never copy the generated mapped-field cache.
- Every remote mutation previews by default and applies only with `--yes`, printing profile, host, and space through `guard::check`.
- Import reads and validates the whole file before the guard. Apply uses the resolved in-memory specs and never re-reads the path.
- Import conflict behavior is default-refuse, `--overwrite`, or `--skip-existing`; the two flags conflict in clap.
- Overwrite uses the documented partial update route plus the field-metadata route. It refuses an `allowHidden` change or an optional-value removal the API cannot express, and never delete-recreates a view.
- Every create or replacement ends with a normalized GET equality check. A failure after any mutation route has returned a decoded success is reported with `applied: true` and is not rolled back.
- A referenced or default data view is never directly deleted. References require `--replace-with`; the current default requires replacement or an earlier explicit unset.
- Every success response is decoded fail-closed. Missing ids, counters, `acknowledged`, `deleteStatus`, or reference entries are `http` errors.
- Fixtures come from real traffic only. Every recorder read and mutation is scoped to unique `elasticctl-sample-*` ids and ends with no marker view, dashboard, or index.
- Newly measured scripted-field, hidden-index, field-metadata, and default facts update the content spec in the same commit as their fixtures.
- Commit messages are plain imperative sentences with no prefixes, agent attribution, trailers, or generated-by text.
- Gates: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -- --test-threads=6`, `cargo deny check advisories bans licenses sources`, `./scripts/check-packages.sh`, `./scripts/check-fixtures.sh`.
- The workspace version stays `0.4.2`; the release flow performs the version bump.

- [ ] **Step 3: Implement the codec and model validation**

Implement the exact public signatures from the Interfaces block. JSON uses `serde_json::to_string_pretty`; YAML uses `serde_yaml_ng::to_string`. Both decode a sequence, reject an empty sequence for import callers only through a separate caller check, and prefix element construction failures with `data view at index N`.

Model extensible maps as `serde_json::Map<String, Value>`, `source_filters` as `Vec<Value>`, and `fields` as a map that section 5 normalization will fill with scripted entries only. Model `type_meta` as `Option<serde_json::Map<String, Value>>`. The two booleans use `#[serde(default)]` and serialize explicitly, so omitted input canonicalizes to `false`. Implement `TryFrom<Value>` through `DataViewSpec::validate`.

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase", deny_unknown_fields)]
pub struct DataViewSpec {
    pub id: String,
    pub title: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub name: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub time_field_name: Option<String>,
    #[serde(default)]
    pub allow_no_index: bool,
    #[serde(default)]
    pub allow_hidden: bool,
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub source_filters: Vec<Value>,
    #[serde(default, skip_serializing_if = "serde_json::Map::is_empty")]
    pub field_formats: serde_json::Map<String, Value>,
    #[serde(default, skip_serializing_if = "serde_json::Map::is_empty")]
    pub runtime_field_map: serde_json::Map<String, Value>,
    #[serde(default, skip_serializing_if = "serde_json::Map::is_empty")]
    pub field_attrs: serde_json::Map<String, Value>,
    #[serde(default, skip_serializing_if = "serde_json::Map::is_empty")]
    pub fields: serde_json::Map<String, Value>,
    #[serde(rename = "type", default, skip_serializing_if = "Option::is_none")]
    pub view_type: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub type_meta: Option<serde_json::Map<String, Value>>,
}
```

- [ ] **Step 3: Implement plan construction**

Read and decode through Task 2 `validate`. For each id, GET the current view when a transport is present; canonicalize it with `normalize`. Default mode refuses all existing ids in one conflict. Skip mode removes them and records `{"id": id, "reason": "exists"}`. Overwrite mode stores snapshots and retains all specs.

For every replacement, `build_patch` compares the canonical values. It puts only changed documented main-route properties in `base`. It excludes `id`, `allowHidden`, and `fieldAttrs`. For field attributes it unions current and desired field names and their metadata keys, copies desired values, and emits `null` for each current key absent from the desired object. An empty base or metadata delta stays `None` or empty and causes no request. Store the finished patch in the plan.

- [ ] **Step 4: Write failing apply race and report tests, then implement**

Tests must prove:

- planned create plus a new current object reports conflict without POST;
- planned replacement plus changed current snapshot reports conflict without update;
- create calls `data_views::create(t, spec, false)` and then GETs the created object;
- replacement sends the stored base patch first when non-empty, then sends the stored field-metadata delta when non-empty, then GETs the object;
- metadata deletion sends `{"fields":{"host.name":{"customLabel":null}}}`;
- no-op writes nothing;
- a base 2xx followed by a metadata error reports `{"id":"dv","applied":true,"error":"base updated; field metadata failed: request timed out"}`;
- a successful create or replacement whose normalized GET differs from the desired spec reports `{"id":"dv","applied":true,"error":"server stored a different data-view spec"}`;
- one failed object does not prevent later objects;
- report field order serializes as `applied,succeeded,skipped,failed,total`.

Apply re-GETs immediately before each object, compares canonical values, and continues after errors. It uses only the stored patch and desired spec after the race check. Every create and replacement ends with a GET, normalization, and exact comparison. Succeeded rows are `{"id": id, "action": "created|replaced|unchanged"}`. Failed rows are `{"id": id, "applied": bool, "error": message}`; `applied` becomes true after the first mutation route returns a decoded success for that object. No partial result is rolled back.
