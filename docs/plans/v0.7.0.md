# elasticctl 0.7.0 MCP Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a stdio MCP server with seven inspection tools, explicit limits,
safe errors, and the existing two binary names.

**Architecture:** Add the published `elasticctl-mcp` library over API/core.
The CLI resolves one target and delegates before rendering. Core transport
limits are opt-in and preserve existing constructors.

**Tech Stack:** Rust 2024, Rust 1.97.1, Tokio, serde, rmcp 3.2.0 and its
schemars re-export, wiremock, assert_cmd, tempfile, insta.

**Spec:** [MCP design](../specs/elasticctl-mcp-design.md), sections 1-9;
[shared design](../specs/elasticctl-design.md). [Research](v0.7-research.md)
records the evidence behind the decisions.

Status: execution authorized on 2026-09-05. Tasks are tracked below.
Development remains at 0.6.2; release and publication need separate approval.

## Global Constraints

- No `clap` type enters the MCP library, API, or core.
- Use `rmcp = "=3.2.0"`, `default-features = false`, with `server`, `macros`, and `transport-io`.
- The target protocol is 2026-07-28. Also test legacy 2025-11-25 initialization through the SDK compatibility path.
- Input line: 262,144 bytes; structured content: 262,144 bytes; complete outbound frame: 1,048,576 bytes; upstream body: 16,777,216 decoded bytes.
- List limits default to 50 and accept integers 1-200. There is no domain result cursor in 0.7.
- Each selector/filter string must contain non-whitespace text and be at most 1,024 UTF-8 bytes. Validate every supplied field before I/O without rewriting its value.
- Four active calls; the fifth returns `busy` immediately. Whole-call timeout defaults to 30 seconds, range 1-120. Shutdown grace is five seconds.
- The catalog is exactly `exceptions_get`, `exceptions_list`, `rules_get`, `rules_list`, `rules_prebuilt_status`, `stack_doctor`, `stack_info`, in that lexical order.
- Tool inputs never select a target, credential, local path, raw URL, command, or mutation. Transport debug is off; redirects are disabled.
- Project content stays in tool data. Descriptions, errors, and logs never copy remote free text. Existing CLI output stays unchanged except new help/catalog entries.
- Existing feature gates and identity contracts remain authoritative. Fixture files come from real traffic and are never hand-edited.
- Local builds use two jobs, tests use four threads, and only one build-heavy process runs at a time.
- Keep development versions at 0.6.2. Release preparation handles the coordinated bump separately.

```rust

    pub call_timeout: std::time::Duration,
    pub allow_query_tools: bool,
}
pub async fn serve_stdio(
    target: elasticctl_core::Resolved,
    options: ServerOptions,
) -> elasticctl_core::Result<()>;
pub async fn serve_io<R, W>(
    target: elasticctl_core::Resolved,
    options: ServerOptions,
    input: R,
    output: W,
) -> elasticctl_core::Result<()>
where
    R: tokio::io::AsyncRead + Unpin + Send + 'static,
    W: tokio::io::AsyncWrite + Unpin + Send + 'static;
```

In 0.7.0, reject `allow_query_tools: true` locally as unsupported. This avoids
publishing a setting that appears effective before the query adapters exist.
`serve_stdio` supplies stdin/stdout to the same bounded `serve_io` path.

Define shared adapter contracts in `server.rs`, `result.rs`, and `catalog.rs`:

```rust
pub struct TargetContext { pub profile: String, pub host: String, pub space: String }
// Internal helpers; no credential or transport is needed for validation.
fn validate_target(target: &Resolved, options: &ServerOptions) -> Result<TargetContext>;
fn validate_text(field: &'static str, value: &str, max_bytes: usize) -> Result<()>;
fn validate_limit(value: usize) -> Result<()>;
pub struct PageInfo {
    pub limit: usize,
    pub returned: usize,
    pub total: Option<u64>,
    pub has_more: Option<bool>,
    pub truncated: bool,
}
pub struct ToolSuccess<T> {
    pub target: TargetContext,
    pub data: T,
    pub page: Option<PageInfo>,
}
pub struct ToolFailure { pub target: TargetContext, pub error: ToolError }
pub struct ToolError {
    pub kind: String, pub http_status: Option<u16>,
    pub code: String, pub message: String,
}
```

All wire types derive `Serialize` and `JsonSchema`; argument types derive
`Deserialize` and `JsonSchema` with `deny_unknown_fields`. Define an untagged
success/error schema union per tool. Keep raw `Profile`, credentials, and
`Resolved` out of derived server debug output. `ServerState::transport()`
returns the one lazily initialized limited core `Transport`; `target()`
returns only `TargetContext`. Every adapter receives `&ServerState`.

`validate_target` checks both resolved URLs, authority, scheme, query/fragment,
doubled schemes, base-path preservation, and the 1-120 second call timeout.
Call it in `serve_io` before protocol startup; `serve_stdio` delegates there.
The text helper checks `trim().is_empty()` and original UTF-8 byte length;
it never changes the value. Schema constraints document these limits, and
runtime validation enforces byte length even when JSON Schema counts characters.

Use a central explicit `ToolId` enum and static catalog. Each adapter module
exports `definitions() -> Vec<Tool>` and an async dispatcher accepting only
its own `ToolId`. The central router resolves the name before decoding
arguments. Per-call cancellation/admission/deadline and result construction
remain in `server.rs`, outside the vertical adapters. An internal adapter
result holds typed data serialized to JSON plus optional `PageInfo`; it is
never a CLI-rendered string.
