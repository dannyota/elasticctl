# elasticctl 0.9.4 Guard Plan

Steps use checkbox (`- [ ]`) syntax. Mark a step done only with its evidence.

**Goal:** Make a 0.9 binary refuse a state mirror written by 0.10, which holds
value lists that 0.9 cannot read.

**Architecture:** One check in the state engine: `state pull`, `state diff`,
and `state push` refuse a mirror directory that holds `value-lists/`. No other
behavior changes.

**Spec:** [shared design 5.6](../specs/elasticctl-design/05-state-engine.md#56-mirrors-from-a-newer-version),
and decision D21 of the 0.10 value lists design on `dev-0.10`.

Status: planned on 2026-11-12, after the 0.9.3 release. Owner decision: the
0.10 design's D21, answered on 2026-11-12.

## Global Constraints

- A mirror without `value-lists/` behaves exactly as in 0.9.3: same output,
  same errors, same files. The one exception is a mirror whose entries cannot
  be inspected: it now fails at the check with `error` and
  `checking the mirror for value-lists/: ...`, where 0.9.3 failed later while
  reading the mirror.
- The refusal happens before any request and before any file is written or
  locked.
- `state pull` is refused too. Pulling into a 0.10 mirror would refresh its
  rules and exceptions and leave its value lists stale, and a later 0.10
  `push` would send the stale values.
- No live run is needed: the change reads only the local directory, and no
  current mirror holds `value-lists/`.

## Task 1: Refuse a 0.10 mirror

**Files:** `docs/specs/elasticctl-design/05-state-engine.md` (5.6, spec
first, same commit), `crates/elasticctl-api/src/state/mirror.rs`,
`crates/elasticctl-api/src/state/pull.rs`, their tests, and the CLI tests that
cover the state commands.

- [ ] `read_mirror` and `pull` refuse when `<dir>/value-lists` exists as any
  kind of entry (directory, file, or symlink), with `ErrorKind::Unsupported`
  and the message `this mirror holds value-lists/, which needs elasticctl 0.10 or later`.
- [ ] Tests: `diff`, `push`, and `pull` each refuse such a mirror before any
  request (wiremock receives nothing) and before any file or lock is created;
  a mirror without it is unchanged, and every existing state test passes
  unedited.
- [ ] Gates: `cargo test --locked --workspace --jobs 2 -- --test-threads=4`,
  fmt, workspace clippy with `-D warnings`, the length checks.
- [ ] Sol review: no path reads or writes a mirror with `value-lists/`, and
  nothing else changed.

## Task 2: Release

- [ ] CHANGELOG: 0.9.4 refuses a 0.10 mirror; 0.9.0 to 0.9.3 do not, which
  is a known limit.
- [ ] The ten gate commands of the 0.9.0 plan on the release commit, then
  release by `docs/releasing.md`.

## Release gates

1. The refusal holds for `pull`, `diff`, and `push`, with no request, file, or
   lock.
2. A mirror without `value-lists/` behaves exactly as in 0.9.3.
3. All gate commands pass on the release commit.
