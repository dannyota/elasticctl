# elasticctl 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Rust CLI that manages Elastic Security detection rules as code — list, inspect, mutate, export, import, and a pull/diff/push state loop — against self-managed, Elastic Cloud Hosted, and Serverless deployments.

**Architecture:** A three-crate Cargo workspace with strictly one-way dependencies: `elasticctl-cli` → `elasticctl-api` → `elasticctl-core`. Command functions return typed values and never print; a render layer turns them into table, JSON, YAML, CSV, or JSONL. Deployment flavor is resolved at runtime by a capability probe rather than by compile-time traits.

**Tech Stack:** Rust 2024 edition on stable 1.97.1, `tokio` + `reqwest` (rustls), `clap` v4 derive, `serde` / `serde_json` / `serde_yaml_ng` / `toml`, `thiserror`, `tabled`, `wiremock`, `assert_cmd`, `insta`.

## Global Constraints

These apply to every task. A task's requirements implicitly include this section.

- **Rust edition 2024**, minimum toolchain **1.97.1**. Set `rust-version = "1.97.1"` in the workspace manifest.
- **Workspace version `0.1.0`**, shared by all crates via `version.workspace = true`. Manifests always carry three components.
- **Publishing:** only `elasticctl-cli` (producing the `elasticctl` binary) may publish. `elasticctl-core` and `elasticctl-api` set `publish = false`.
- **Dependency direction is one-way:** `cli` → `api` → `core`. `elasticctl-core` must not depend on `elasticctl-api` or on `clap`. `elasticctl-api` must not depend on `clap`.
- **Command functions return typed values and never print.** No `println!`, no `String` returns standing in for output. Rendering happens only in `elasticctl-cli::render`.
- **Every mutation is a dry run by default.** `--yes` applies. Both the preview and the apply print a banner naming profile, host, and space.
- **`state push` never deletes remote rules.** Local absence is never a delete instruction.
- **Rule identity for state matching is always `rule_id`** — never the display name, never the volatile `id`.
- **Secrets are redacted in all output**, including `--debug` HTTP logs.
- **Error kinds** are exactly: `auth`, `permission`, `not_found`, `conflict`, `unsupported`, `http`, `connection`, `timeout`, `error`.
- **Exit codes:** `0` success, `1` error, `2` usage.
- **Required Kibana headers:** `kbn-xsrf: true` on every non-GET; `elastic-api-version: 2023-10-31` on versioned public APIs.
- **Volatile rule fields (strip before diffing, 7):** `id`, `created_at`, `created_by`, `updated_at`, `updated_by`, `revision`, `version`.
- **Server-default rule fields (fill before diffing a sparse local file, 16):** `actions`, `author`, `exceptions_list`, `false_positives`, `immutable`, `max_signals`, `output_index`, `references`, `related_integrations`, `required_fields`, `risk_score_mapping`, `rule_source`, `setup`, `severity_mapping`, `threat`, `to`.
- **Never commit `.env`.** It is gitignored and mode `0600`. Never echo the API key into output, logs, commit messages, or test fixtures.
- **Fixtures are recorded, never hand-edited to pass.** Re-record instead.
- **Design source of truth:** `docs/specs/elasticctl-design.md`. Read it before changing behaviour.

## Trim line

If 0.1.0 needs to ship sooner, Tasks 15 (`rules preview`), 17 (`completion`, `commands`) can slip to 0.1.1 without weakening the release — the rules-as-code loop still works without them. Do not trim Tasks 1–14 or 16.

```rust
//! The error taxonomy. Every failure that reaches the user is classified here.

use serde_json::{Value, json};

/// A stable error classification. These strings are part of the CLI's public
/// API — changing one is a breaking change requiring a minor version bump.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ErrorKind {
    Auth,
    Permission,
    NotFound,
    Conflict,
    Unsupported,
    Http,
    Connection,
    Timeout,
    Error,
}

impl ErrorKind {
    pub fn as_str(&self) -> &'static str {
        match self {
            Self::Auth => "auth",
            Self::Permission => "permission",
            Self::NotFound => "not_found",
            Self::Conflict => "conflict",
            Self::Unsupported => "unsupported",
            Self::Http => "http",
            Self::Connection => "connection",
            Self::Timeout => "timeout",
            Self::Error => "error",
        }
    }

    pub fn from_status(status: u16) -> Self {
        match status {
            401 => Self::Auth,
            403 => Self::Permission,
            404 => Self::NotFound,
            409 => Self::Conflict,
            _ => Self::Http,
        }
    }
}

#[derive(Debug, Clone, thiserror::Error)]
#[error("{message}")]
pub struct Error {
    pub kind: ErrorKind,
    pub http_status: Option<u16>,
    pub message: String,
}

impl Error {
    pub fn new(kind: ErrorKind, message: impl Into<String>) -> Self {
        Self { kind, http_status: None, message: message.into() }
    }

    pub fn with_status(kind: ErrorKind, status: u16, message: impl Into<String>) -> Self {
        Self { kind, http_status: Some(status), message: message.into() }
    }

    /// Classify an HTTP error response.
    ///
    /// Two envelope shapes exist in the wild and both must be handled:
    /// Kibana returns `{"statusCode":..,"error":..,"message":..}`, while the
    /// Elastic Cloud edge proxy returns `{"ok":false,"message":".."}`. The
    /// edge shape also appears for a hostname that no longer resolves to a
    /// live project, which happens after a project rename.
    pub fn from_response_body(status: u16, body: &str) -> Self {
        let kind = ErrorKind::from_status(status);
        let message = serde_json::from_str::<Value>(body)
            .ok()
            .and_then(|v| v.get("message")?.as_str().map(str::to_owned))
            .unwrap_or_else(|| {
                let trimmed = body.trim();
                if trimmed.is_empty() {
                    format!("HTTP {status}")
                } else {
                    format!("HTTP {status}: {trimmed}")
                }
            });
        Self { kind, http_status: Some(status), message }
    }

    /// The single JSON object written to stderr when a command fails.
    pub fn to_envelope(&self) -> Value {
        let mut inner = json!({ "kind": self.kind.as_str(), "message": self.message });
        if let Some(status) = self.http_status {
            inner["http_status"] = json!(status);
        }
        json!({ "error": inner })
    }
}

pub type Result<T> = std::result::Result<T, Error>;
```
