# elasticctl 0.5.2 Content Conformance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove data-view and dashboard transfer on Serverless, Hosted, and self-managed Kibana, enforce zero content residue, and ship the bounded release review.

**Architecture:** Extend the existing live harness with dashboard/data-view/default cleanup and baseline state. Register one ninth `content` contract gated by `Feature::Dashboards`. Run the contract through the existing conformance controller and matrix; do not build a second runner.

**Tech Stack:** Rust 2024, assert_cmd live tests, elasticctl API modules, xtask conformance controller, bash/jq report gate, Podman self-managed lab.

**Spec:** [`docs/specs/elasticctl-content-design.md`](../specs/elasticctl-content-design.md) sections 10 and 13-16. Harness contracts are in [`docs/specs/elasticctl-design.md`](../specs/elasticctl-design.md) section 8.3.

## Global Constraints

- The ninth contract is exactly `content_transfers_data_views_and_dashboards_without_residue`, registered as `content` with `features: &[DASHBOARDS]`.
- Every created id starts with `elasticctl-live-`; the scratch index contains `elasticctl-live` and the data-view title matches only that index.
- Cleanup registers ids before the mutation that creates them. Dashboard delete and verified original-default restoration both succeed before data-view delete; all data-view deletes succeed before marker-index delete. A failed prerequisite retains its dependents for the Drop retry.
- Content tolerates no residue: marker dashboards, data views, and indices are zero, and the exact default data-view id equals the captured baseline after every contract.
- Existing triage's closed-alert exception remains the only residue exception. Do not weaken rule, exception, case, alert, or index baselines.
- Except for restoring the exact captured default, every remote mutation targets an explicit marker id. Saved Objects export receives an explicit marker dashboard object. No shared-space content enters logs or reports.
- The Serverless project prebuilt corpus remains read-only ground truth. Its before/after counts must match.
- `TargetState` capture fails closed if a required content route cannot be decoded. Below the dashboard floor, only the dashboard marker partition is gated to zero so the contract can report its existing `unsupported` skip.
- Reports contain only flavor, version, contract, result, and error class. Private failures remain under ignored `target/conformance-private/` logs.
- Review scope is the 0.5 content delta and its invariant-bearing transport/guard/harness boundaries. A confirmed finding requires a regression and spec update when behavioral.
- Credentials come only from the main checkout `.env`, are never printed, and are never copied into a worktree. Hosted is never stopped or suspended. Lab runs last and is torn down with volumes.
- Commit messages are plain imperative sentences with no prefixes, agent attribution, trailers, or generated-by text.
- Gates: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -- --test-threads=6`, `cargo deny check advisories bans licenses sources`, all three scripts, and package dry run.
- The workspace version stays `0.5.1`; the release flow performs the version bump.

- [ ] **Step 1: Add failing offline cleanup-registration tests**

Extend the existing `LiveCleanup::for_test` unit coverage:

```rust
#[test]
fn cleanup_tracks_content_and_original_default() {
    let mut cleanup = LiveCleanup::for_test();
    cleanup.dashboard("elasticctl-live-dashboard");
    cleanup.data_view("elasticctl-live-view");
    cleanup.restore_default_data_view(Some("original-view".to_string()));
    assert!(cleanup.dashboards.contains("elasticctl-live-dashboard"));
    assert!(cleanup.data_views.contains("elasticctl-live-view"));
    assert_eq!(cleanup.default_data_view, Some(Some("original-view".to_string())));
}
```

Also assert a second `restore_default_data_view` registration with a different value panics: cleanup ownership is captured once, before mutation.

- [ ] **Step 2: Implement cleanup order and idempotence**

`delete_dashboard` calls `elasticctl_api::dashboards::delete` and tolerates `NotFound`. `restore_default` first reads the current default. It no-ops and clears the lease when the baseline is already restored, restores and verifies only when the current id is one of the owned marker data views, and refuses an unexpected value without a POST. `delete_data_view` calls the low-level direct DELETE only from cleanup, after every dashboard delete and default restoration succeeds, and tolerates `NotFound`. Marker-index deletion runs only after every data-view delete succeeds.

`clean()` order becomes:

```text
close marker alerts
delete cases and case scopes
delete dashboards
restore captured default
delete data views
delete rules
delete exception lists
validate item parents
delete indices
```

Every new step uses the existing three-attempt `retry` wrapper. If no original default was registered, cleanup does not change the default. A failed dashboard delete or default restore skips all data-view and dependent index deletes; a failed data-view delete skips the dependent index delete.

- [ ] **Step 3: Add failing baseline-reader tests around pure decisions**

Extract a pure helper and test this truth table:

```rust
fn content_residue_is_clean(
    marker_dashboards: usize,
    marker_data_views: usize,
    current_default: Option<&str>,
    original_default: Option<&str>,
) -> bool {
    marker_dashboards == 0
        && marker_data_views == 0
        && current_default == original_default
}
```

Zero/zero/equal is clean; either marker count or any default change is dirty.

- [ ] **Step 4: Implement marker/default reads and baseline integration**

Data views: call `data_views::list`, then retain ids beginning `LIVE_PREFIX`. Dashboards: page `dashboards::search` without a query, then exact-filter ids beginning `LIVE_PREFIX`; the public query is not an id-prefix contract. Default: call `data_views::get_default`, reject a marker or whitespace-only id, and resolve any nonempty id before the first mutation so restoration is known to be possible.

`capture_baseline` requires zero marker content and stores the validated default. `assert_clean_baseline` repeats both marker reads and compares the exact current default to baseline. Keep every existing rule/list/index/triage assertion. Offline tests cover an already-restored no-op, an owned-marker restore, an unexpected nonmarker default, dashboard-delete failure, data-view-delete failure, and the dependent-delete gates.

Run: `cargo fmt --all && cargo test -p elasticctl --test live`

- [ ] **Step 2: Implement the content probe in the approved order**

Use `std::fs::write` only inside the test fixture setup; production edits still use normal implementation rules. Every command runs through the existing `checked` helper and parses JSON reports when applicable.

1. Register index, first view, second view, dashboard, and captured original default in cleanup before any writes.
2. Create and seed the marker index through `Transport`, refresh it.
3. Write the first data-view artifact; run `data-views import --path first-view.json --yes`; assert one success and GET title/id.
4. Run `data-views default set first_view --yes`; assert default now equals first.
5. Write dashboard artifact description `initial`; run `dashboards import --path dashboard.json --yes`; assert one success and GET has one data-view ref equal to first.
6. Run dashboard list/get/export. Decode the portable export and assert exact id plus no `meta`. Re-import that export with `--overwrite --yes`; assert no loss.
7. Rewrite description to `updated`; import with `--overwrite --yes`; assert GET description changed and panel remained.
8. Run `dashboards bundle export dashboard --out dashboard.ndjson`; scan with `saved_objects::scan_bundle`; assert one dashboard and one index-pattern.
9. Restore the original default with `data-views default set original_default --yes` or `default unset --yes`. Delete dashboard and first view through guarded CLI commands; assert both 404.
10. Run `dashboards bundle import --path dashboard.ndjson --yes`; assert dashboard and first view are recreated with the same ids and reference.
11. Import the second data-view artifact. Set first as default again. Run `data-views delete first_view --replace-with second_view --yes`; assert first is 404, dashboard refs contain second and not first, and default equals second.
12. Restore original default again. Delete dashboard and second view through guarded CLI commands. Delete index through transport. Assert all marker reads are empty before returning.

- [ ] **Step 3: Add the ignored test shell**

Follow the existing contract skeleton: `skip_unless_live`, `_serialize = serialize_live()`, temporary config and directory, `capture_baseline`, unique names, cleanup registration, closure returning `TestResult`, and `conclude(result, &mut cleanup, baseline)`.

```rust
#[test]
#[ignore = "requires a live stack"]
fn content_transfers_data_views_and_dashboards_without_residue() {
    if skip_unless_live() {
        return;
    }
    let _serialize = serialize_live();
    let dir = tempfile::tempdir().unwrap();
    let config = write_live_config(dir.path());
    let profile = live_profile();
    let baseline = capture_baseline(&config, &profile).unwrap();
    let index = unique_name("content-index");
    let first_view = unique_name("data-view-a");
    let second_view = unique_name("data-view-b");
    let dashboard = unique_name("dashboard");
    let mut cleanup = LiveCleanup::new(config.clone(), profile.clone());
    cleanup.index(index.clone());
    cleanup.data_view(first_view.clone());
    cleanup.data_view(second_view.clone());
    cleanup.dashboard(dashboard.clone());
    cleanup.restore_default_data_view(baseline.default_data_view.clone());

    let result = (|| -> TestResult {
        content_probe(
            &config,
            &profile,
            dir.path(),
            &index,
            &first_view,
            &second_view,
            &dashboard,
            &mut cleanup,
        )
    })();
    conclude(result, &mut cleanup, baseline);
}
```
