# elasticctl 0.1.2 Implementation Plan

A patch release finishing the detection-rules vertical. Three slices: scoped
state operations, a one-request corpus read, and flavor detection that no
longer guesses from a hostname.

Everything here is additive under 11.1. No command, flag, JSON field, error
kind, or exit code changes meaning. `skipped_remote_only` shifts only when a
selector is passed, and selectors did not previously exist.

## 1. Global constraints

- The spec is already updated for this release. `docs/specs/elasticctl-design.md`
  sections 3.1, 5.2, 5.3, 7.6, 8, 12, and 13 describe the target behaviour.
  Where this plan and the spec disagree, the spec wins and the plan is wrong.
- Command functions return typed values and never print.
- `clap` types stay out of `-api` and `-core`.
- Every mutation remains a dry run by default.
- No task asserts an API shape that is not measured. Section 3 lists what was
  measured and when; nothing in this release is pending verification.
- Fixtures are recorded, never hand-written or hand-edited.

## 2. Design decisions made in this plan

### 2.1 Selector grammar is the one already in the tool

`pull`, `diff`, and `push` take positional selectors and `--tag`, identical to
`rules export`, `enable`, `disable`, and `delete`. A second grammar for the
same idea — `--rule-id` repeated, say — would mean the tool answers "which
rules?" two different ways depending on which command you are in.

`--dir` stays a flag, so positionals are unambiguous.

### 2.2 Selection resolves local-first for diff and push

`pull` reads from the stack, so its selectors name stack rules.

`diff` and `push` act on the local directory. A selector matching a local
`rule_id` or `name` wins; only an unmatched selector falls through to a remote
lookup. This is not a preference — a locally-added rule exists in no remote
index, so remote-only resolution would make scoped `push` unable to create the
rule you just wrote, which is the single most likely reason to reach for it.

An ambiguous local name is refused naming both `rule_id`s. Identity is
`rule_id`; a display name that has stopped being unique is not resolved by
guessing.

### 2.3 Scoped drift narrows both sides

Selection filters local and remote before `Drift::compute`, so the remote read
becomes one `rule_id`-filtered `_find`. Computing full-corpus drift and merely
gating what gets applied would keep the corpus read on every scoped run and
forfeit the point.

`RemoteOnly` survives inside a selection — `--tag prod` can select a remote
rule with no local file — and `push` still never deletes it.

Reports gain `selected` and `local_total`; the guard banner names the
selection. A scoped apply that reads identically to a full one defeats the
banner.

### 2.4 One request, and no concurrency

Measured against 2,066 rules on Serverless 9.6.0:

| `per_page` | returned | time |
|---|---|---|
| 100 | 100 | 0.78 s |
| 1000 | 1000 | 1.36 s |
| 2100 | 2066 | 2.38 s |
| 10000 | 2066 | 2.64 s |
| 10001 | — | 400 |

The 400 reads `Result window is too large, from + size must be less than or
equal to: [10000]`. The bound is Elasticsearch's result window applied to the
*sum*, not a page-size cap.

The concurrency work discussed during design is therefore dropped, not
deferred. Parallelising pages 2..N requires a page size small enough to produce
many pages, and the window then caps the readable total at 10,000 regardless.
Concurrency cannot buy what the window forbids. Raising the page size gets the
whole corpus in one request; there is no page 2 left to fetch.

The window is also a ceiling on the command, and that needs an explicit
refusal. Returning the first 10,000 rules as if they were the corpus would make
`state diff` report every unread rule as remote-only and `state pull` write a
mirror missing them. Silent truncation is worse than failing.

### 2.5 Flavor comes from an edge header

Measured on Hosted 9.5.1 in `gcp-asia-southeast1`, recorded in
`tests/fixtures/ech-9.5.1`:

1. `build_flavor == "serverless"` → Serverless.
2. `x-found-handling-cluster` present → Hosted.
3. Otherwise self-managed.

Hosted reports `build_flavor: "traditional"`, byte-identical to self-managed,
so no field of the status body separates them. Serverless carries the same edge
header, which is why the `build_flavor` test must come first — reversing them
classifies every Serverless project as Hosted.

Hostname matching stays as a last resort for a deployment behind a
header-stripping proxy. It is no longer the primary answer.

### 2.6 What this release deliberately does not do

- **Parallelise anything.** See 2.4. The measurement removed the reason.
- **Read a corpus larger than 10,000 rules.** `_find` cannot, by any
  combination of `page` and `per_page`. The command refuses and names the
  limit. An export-based reader is a design of its own.
- **Refresh the self-managed fixture set.** `traditional-9.5.1` holds 10
  fixtures against 14 for the other two flavors. It needs a `lab/` session, not
  a code change, and it does not gate this release.
- **Prove the negative half of flavor detection.** That a self-managed stack
  emits no `x-found-handling-cluster` follows from there being no Cloud proxy
  in front of one, but it is an inference until a `lab/` recording exists. The
  fixture format carries headers so that recording can prove it later.
- **Change any default.** Every command without selectors behaves exactly as
  in 0.1.1.

worktree. Task 4 depends on Task 3's module existing. Task 5 is last because it
bumps the version.

## 5. Tasks

### Task 1: Headers reach the capability probe

`Transport` returns response headers alongside the body. `Capabilities::probe`
decides flavor by the order in 2.5. The fixture format gains a `headers` object
and `xtask record` populates it.

Already applied in this session and part of this task's diff:
`ELASTICCTL_FIXTURE_FLAVOR` in `xtask/src/main.rs`, which stops a Hosted
recording overwriting `traditional-9.5.1`. It is uncommitted.

Acceptance:

- The probe classifies Hosted from a recorded fixture carrying the header, not
  from its hostname.
- Serverless still classifies as Serverless when the same header is present.
- A response with no such header and `build_flavor: "traditional"` classifies
  as self-managed.
- Hostname matching still classifies a Cloud-suffixed host when the header is
  absent.
- `--debug` output is unchanged, byte for byte. Headers are carried, never
  logged.
- The Hosted `status` fixture is re-recorded with headers while the deployment
  is live, and `tests/fixtures/ech-9.5.1` is committed.

### Task 2: One request for the corpus

Raise the page size to the result window. Refuse a corpus larger than the
window with an error naming the limit and pointing at `rules export`.

Acceptance:

- A corpus of 2,066 is read in one request. The fixture test proves the request
  shape; the live test proves the timing claim.
- `total` above 10,000 produces a classified error naming the 10,000 limit, not
  a truncated list and not a raw 400.
- `MAX_PAGES` and the pagination loop are removed or reduced to whatever the
  refusal path still needs. Dead backstops do not survive.
- Existing `rules list` output is unchanged for any corpus under the window.

### Task 3: One selection resolver

Extract selector-and-tag resolution out of `cmd::rules::export_selection` into
`elasticctl-api::selection`, taking a resolution mode so `pull` resolves
remotely and `diff`/`push` resolve local-first.

Acceptance:

- `rules export` behaviour is unchanged; its existing tests pass untouched.
- A selector resolving to nothing is refused naming the selector.
- A `--tag` matching nothing is refused naming the tag, even when a selector
  also resolved.
- An ambiguous local name is refused naming both `rule_id`s.
- The module has no `clap` types in its signature.

### Task 4: Selectors on the state commands

Add positional selectors and `--tag` to `pull`, `diff`, and `push`. Narrow both
sides before `Drift::compute`. Report `selected` and `local_total`. Name the
selection in the guard banner.

Acceptance:

- `state push --dir rules/ <id>` reads one filtered `_find`, not the corpus.
- A locally-added rule is selectable by name and by `rule_id` before it exists
  remotely.
- `RemoteOnly` inside a selection is still reported and still never deleted.
- The banner names the selection, and a dry run reports the same `selected` and
  `local_total` as the apply.
- No selectors means byte-identical output to 0.1.1.
- Tests live in `tests/state_selection.rs`.

### Task 5: Release

Version bump, changelog, tag. The build matrix is proven — 0.1.1 shipped a
complete 7-target asset list — so no `-rc` tag.
