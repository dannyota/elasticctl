# elasticctl 0.6.2 Fleet Conformance Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement each task. The coordinator owns Git operations and verification.

**Goal:** Prove Fleet policy transfer on all three deployment flavors and close the deferred integration-policy selector defect.

**Architecture:** Keep policy behavior in the existing API orchestration. Add shared, private Fleet baseline reads to the test-support crate, then extend the existing live test and conformance runner. Fleet cleanup uses nonce ownership and one-shot mutations.

**Tech Stack:** Rust 2024, Tokio, wiremock, assert_cmd, xtask, Bash/jq, Podman.

**Spec:** [Fleet design](../specs/elasticctl-fleet-design.md), especially sections 9 and 14; [shared design](../specs/elasticctl-design.md), especially section 8.3.

## Constraints

- The tenth contract is `fleet_transfers_agent_and_integration_policies_without_residue`, registered as `fleet` with `features: &[FLEET_POLICIES]`.
- Preserve the 9.5.1 feature floor, existing output shapes, and `cli -> api -> core` dependency direction.
- Every created policy id and name starts with `elasticctl-live-`. Each run adds a nonce to its policy descriptions and uses empty agent monitoring.
- Register exact ids before creating them. Cleanup rechecks nonce, id, ownership, agents, and attachments before each one-shot mutation. Never send `force` or replay an ambiguous mutation blindly.
- Delete integrations before parents. A remaining integration blocks parent cleanup and package uninstall.
- Install exact `system` only when absent, using the status response's nonempty `latestVersion`. Claim that version before the attempt, observe the outcome, and uninstall only a version this run installed. Pre-existing packages are never removed.
- Public evidence contains only flavor, actual version, contract, result, and error class. Raw output stays in ignored private logs.
- Keep the Hosted deployment running. Read live configuration only inside command processes from the main checkout. Never print or copy `.env`.
- Update the spec before changing behavior. Remove a closed item from the current backlog. Do not edit recorded fixtures by hand.
- Local builds use `--jobs 2`; tests use `--test-threads=4`. Run one build-heavy command at a time.
- Keep versions at 0.6.1 during development. Release preparation, tagging, and crates.io publishing are separate steps.

### Task 2: Audit Fleet state in the conformance controller

**Interface:** Add a private tooling module exported as `elasticctl_api_test_support::fleet`. It depends only on core transport and JSON, avoiding an API dev-dependency cycle.

```rust
pub type PackageInventory = std::collections::BTreeMap<String, String>;
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct FleetState {
    pub agent_policies: std::collections::BTreeSet<String>,
    pub integration_policies: std::collections::BTreeSet<String>,
    pub packages: PackageInventory,
}
impl FleetState {
    pub async fn capture(t: &elasticctl_core::Transport)
        -> elasticctl_core::Result<Self>;
    pub fn markers_empty(&self) -> bool;
}
pub async fn installed_packages(t: &elasticctl_core::Transport)
    -> elasticctl_core::Result<PackageInventory>;
```

- [ ] Add offline tests for malformed inventory, duplicate package names, short reads, invalid cursors, reordered inventory, paging contradictions, and markers present by id even when their name differs. Use wiremock responses as adversarial tests, never as recorded fixtures.
- [ ] Read installed packages with `/api/fleet/epm/packages/installed?perPage=1000&sortOrder=asc`. Retain only installed `(name, version)` pairs. Follow the recorder's strict one-page envelope validation, including `total <= 1000`, exact count, and at most two scalar `searchAfter` values.
- [ ] Read policies by the existing `created_at` paging contract, with simplified integrations. Validate page, per-page, total stability, ids, names, duplicates, and completeness. Retain only ids whose id or name starts with `elasticctl-live-`; discard all other payload data.

### Task 3: Exercise Fleet transfer and prove cleanup safety

**Interface:** Add `mod fleet` under `tests/live.rs` using `tests/live/fleet.rs`. The root ignored test keeps the exact contract name and delegates to the module. The module can use parent CLI helpers and the shared Fleet audit types. Keep the existing live tests' cleanup behavior intact.

- [ ] Build a Fleet cleanup guard holding the profile, per-run nonce, owned parent/integration ids, baseline inventory, and optional claimed package version. It retains failed cleanup leases for Drop. Each attempt performs fresh exact reads; one-shot transport sends each mutation once.
- [ ] Add offline safety tests before implementation: a different nonce is never deleted; missing or malformed ownership fields fail closed; unknown or nonzero agent counts block parent deletion; an attached parent sends no delete; integration failure blocks parent/package deletion; pre-existing system is never removed; a changed version is never removed; ambiguous create/delete uses exact observation without replay; package drift blocks success.
- [ ] Implement cleanup in dependency order. A package removal requires confirmed owned install, no remaining owned policy, no new unowned consumer, the exact installed version, and an inventory equal to baseline plus that coordinate. Observe the inventory after removal. Never include values or raw payloads in public progress.
- [ ] Begin the live contract with setup, the existing rule/content/triage baseline, and a clean Fleet snapshot. Refuse markers before package installation. Recheck package inventory and exact version immediately before bootstrap or policy creates.
- [ ] Ensure system as specified. For a fresh install, require complete evidence of the exact resulting version and inventory; an unreadable or competing result is a cleanup failure, not permission to uninstall.
- [ ] Import a marker agent artifact with explicit id, empty monitoring, and nonce description. Check preview does not create, then apply, get, marker-filtered list, JSON/YAML export, default conflict, skip, changed overwrite, unchanged overwrite, and exact normalized round trip.
- [ ] Materialize system defaults with one nonce-owned bootstrap integration using `inputs: {}` through a direct one-shot create, as the recorder does. Export through production normalization to obtain the complete nonsecret input map. Delete and verify bootstrap absence and parent detachment before the actual import lifecycle. Register bootstrap ownership before its create.
- [ ] Exercise the same preview/apply/get/list/export/conflict/skip/overwrite/unchanged/round-trip lifecycle for the actual integration. Require exact parent ids and package coordinate.
- [ ] While attached, invoke agent delete and require client-side `conflict`. Pair this live proof with a wiremock CLI regression that proves zero requests to the parent-delete route; remote unchanged state alone is insufficient evidence of no request.
- [ ] Delete integration before parent. Re-import both exported artifacts in dependency order, require the same ids and contents, and delete both again. Finish Fleet cleanup, then the existing baseline audits. Classify cleanup failure ahead of ordinary contract failure.
- [ ] Run `cargo test --locked -p elasticctl --test live --jobs 2 -- --test-threads=4` and compile the exact ignored test without running it. Review the ownership and ambiguity paths with Sol before live execution.
