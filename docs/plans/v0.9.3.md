# elasticctl 0.9.3 Cleanup Plan

Steps use checkbox (`- [ ]`) syntax. Mark a step done only with its evidence.

**Goal:** Close the open limits that the 0.8.2 to 0.9.2 reviews carried
forward, without changing any tool, schema, limit, error code, or consent
rule.

**Architecture:** Keep the 0.9.2 server. Add one test-only server option,
change the live harness and two offline tests, and correct stale research
notes. The only runtime change is the new test option.

**Tech Stack:** Rust and Tokio, wiremock, the live harness, xtask, the CI lab
(`live-lab.yml`), and the Hosted and Serverless test targets.

**Spec:** [MCP mutation design](../specs/elasticctl-mcp-mutation-design.md)
sections 5.4, 8.4, and 9; [shared conformance contract](../specs/elasticctl-design/08-testing.md#83-cross-flavor-live-conformance).

Status: planned on 2026-11-12, after the 0.9.2 release.

## Global Constraints

- No tool, schema, limit, error code, consent rule, or CLI output changes. A
  fix that needs one is a spec change and goes to the owner first.
- The test option changes nothing unless a test sets it. Production plans keep
  the 900-second life of design 5.4.
- No local lab starts (mutation design D35). The self-managed leg runs in
  `live-lab.yml`.
- A runtime change after a live pass reruns that pass on every flavor
  (mutation design 9.4). Task 2 adds a runtime change, and Task 3 changes how
  every live contract authenticates, so Task 5 runs the thirteen-contract
  matrix at the release head.
- Keep development versions at the released 0.9.2 value.

## Task 2: End-to-end expiry audit

Closes the 0.9.2 evidence limit: no test drives a plan's expiry through the
server. Each session runs on its own thread with a fresh runtime
(`src/server/runtime.rs`), so a test cannot advance its clock.

- [ ] Add `plan_life: Option<Duration>` to `TestOptions`, beside
  `legacy_wait`. `None` keeps `PLAN_LIFE_SECS`. Production code never sets it,
  and `ServerOptions` does not change.
- [ ] The consent text's "Expires in <n> min." and every plan projection use
  the same life value, so a test plan and its text agree.
- [ ] In `tests/mutation_conformance/audit.rs`, add `expired`: a plan made
  with a short life, then `plan_apply` after it ends. Require `plan_expired`,
  no write, and exactly `plan_created` then `plan_closed` with
  `state: "expired"`, with the exact fields and the Unix-second `ts` window of
  the other scenarios. The wait is bounded and polls a condition.
- [ ] Unit tests: `None` keeps 900 seconds; a set value reaches the store.
- [ ] Gates: `cargo test --locked -p elasticctl-mcp --jobs 2 -- --test-threads=4`, fmt, workspace clippy with `-D warnings`, the length checks.
- [ ] Astra adversarial review: production behavior unchanged, the option
  unreachable from the CLI and MCP surfaces, and the test fails if expiry
  stops emitting `plan_closed`.

## Task 3: Keep the API key out of the live config

Closes the limit open since 0.9.0: `write_live_config` writes
`ELASTICCTL_API_KEY` into the run's `config.toml` (mode 0600, in a temporary
directory).

- [ ] The live config holds no secret. Each child gets the key only through
  its environment, never in its arguments or a file.
- [ ] Decide and record two points first. The mutation contract's children
  start through `offline_child_command`, which removes every target override
  (`tests/live/mcp_smoke.rs`). An environment key is an identity override,
  so the target's `source` becomes `Flags`, not `Profile`
  (`elasticctl-core` `Config::resolve`). Nothing a contract asserts may
  change because of either.
- [ ] Offline tests prove the written config has no `api_key` and that each
  live child command carries the key only in its environment.
- [ ] Sol adversarial review: no key in any file, argument, log, or public
  output; every contract still authenticates; cleanup unchanged.

## Task 4: Gate the shared permit check

Closes the 0.8.2 limit: `assert_a_permit_is_free` in
`tests/detection_coverage_tool.rs` holds three calls with a mock delay and
expects a fourth answer within 500 ms. On a slow runner the held calls can
finish first, and the check then proves nothing.

- [ ] Hold the three calls behind an explicit gate the test releases, as the
  0.9.2 conformance target does for its concurrency check. Prove the three
  are inside their permits before sending the fourth, and release the gate
  only after the fourth answers.
- [ ] No other caller of the helper may become timing dependent; the 0.8.2
  attempt failed on that.
- [ ] Run the target ten times in a row with `--test-threads=4`.
- [ ] Astra adversarial review: the check fails if a released permit is not
  freed, and it cannot pass by timing.
