# elasticctl 0.10.0 Value Lists Implementation Plan

Steps use checkbox (`- [ ]`) syntax. Mark a step done only with its evidence.

**Goal:** Manage Elastic Security value lists as code: a `value-lists`
command group, and value lists in the state mirror, reconciled exactly and
never in a state that suppresses more than the old or the new policy.

**Architecture:** As [the value lists design](../specs/elasticctl-value-lists-design.md)
section 8: three send-once calls in `-core`, a `value_lists` module and state
engine changes in `-api`, and the command group in the CLI. `-mcp` does not
change.

**Tech Stack:** Rust and Tokio, wiremock, the xtask recorder, the live
harness, the CI lab (`live-lab.yml`), and the Serverless and Hosted test
targets.

**Spec:** [value lists design](../specs/elasticctl-value-lists-design.md),
all sections; [research](v0.10-research.md), V1 to V12.

Status: planned on 2026-11-12. 0.9.4 ships first (design D21).

## Global Constraints

- The design wins over this plan. A gap found while implementing goes back to
  the design first, then to the owner if it changes a decision.
- Every remote write is sent once, on a transport without retries (design
  6). Every value write is followed by its read-back (D14).
- No write may pass a state the design forbids: more than 200 stored dash
  values (D12), an empty referenced list (D28), or a change inside a changing
  list's dependency cone (D27).
- Offline tests copy recorded responses only. Task 2 records them before
  Tasks 4 to 6 write tests that need them.
- A mirror without `value-lists/` produces exactly the 0.9.3 output from
  `state pull`, `diff`, and `push`, apart from the D4 refusal that replaces
  0.9's preview line (design 7.4).
- Live probes start and end at baseline; the Cloud targets end "not
  bootstrapped" when they started so (D5).
- Development versions stay at the released 0.9.4 value until the release
  task.

## Task 1: Send-once transport calls

- [ ] `patch_once`, `post_multipart_once_named`, and `delete_once_response`
  as design 8.1 says, each on the one-shot client with an attempt limit of 1.
- [ ] Tests with wiremock: each sends exactly one request on a 503, a
  timeout, and a connection reset; `delete_once_response` returns a 409 body
  and status without an error; existing transport tests pass unedited.
- [ ] Gates: `cargo test --locked -p elasticctl-core --jobs 2 -- --test-threads=4`, fmt, workspace clippy, lengths.

## Task 2: Record value-list fixtures

- [ ] Extend the recorder with the value-list pass of design 9.1, using the
  `elasticctl-live-vl-` prefix and restoring "not bootstrapped" where it
  started so.
- [ ] Run it on Serverless, Hosted, and the lab (the lab through a
  `live-lab.yml` dispatch on an unmerged branch). Check every fixture with
  `./scripts/check-fixtures.sh`.
- [ ] Review: no host, user, key, or object id in any fixture.

## Task 3: Model, codec, and validation

- [ ] The container and values files, the parsing order, the readable and
  canonical levels, and the stem rule (design 3 and 7.2).
- [ ] Validation of design 5.1, the projected dash and empty states of 5.2
  and 5.3, and the size warnings of 5.4, as pure functions.
- [ ] Tests for every row and boundary that design 9.2 lists for these
  sections.

## Task 4: Reads, scan, plan, and apply

- [ ] The reads: bootstrap state, `_find` with `cursor`, container read,
  `_export` into stored values and the set.
- [ ] The scan of installed references (D26), failing closed.
- [ ] The plan: container action, value adds and removes, the D22 order, and
  the D12 and D28 checks on all three states.
- [ ] The apply: create, update, the two phases, read-back with its budget,
  uncertain writes, outcomes, and evidence (design 6 and 7.5); `delete` and
  `init`.
- [ ] Tests from recorded responses for every case design 9.2 lists for these
  sections.

## Task 5: State engine

- [ ] The selected set, retained references, the layout and stems, the
  `pull` refusal (D23), the `value_lists` diff block and `clean`, the `push`
  checks (D4, D12, D27, D28), the apply order, the container re-read, and the
  report and summary (design 7).
- [ ] `doctor`'s new `value_list_index` message.
- [ ] Tests from design 9.2 for these sections; every existing state test
  passes, edited only where the design changes behavior.

## Task 6: CLI

- [ ] The `value-lists` commands (design 4), the structured guard preview,
  the `commands` tree, and the completions.
- [ ] Snapshots for help, the tree, and each command's output; existing
  snapshots change only for the new group and the `doctor` text.

- [ ] Register it in the controller, the validator (`CONTRACTS_V10` for

- [ ] Offline tests for its classification and cleanup.
