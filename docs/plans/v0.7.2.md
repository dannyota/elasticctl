# elasticctl 0.7.2 MCP Conformance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the complete MCP surface through the eleven-contract release
matrix and two independent product clients, fixing defects supported by that
evidence.

**Architecture:** Retain the 0.7.1 server, tools, and live harness. Register
the existing live MCP read test as the eleventh conformance contract, extend
the controller and validator, and fill the remaining protocol test gaps.
Provision sample objects outside MCP through reviewed test code; MCP performs
only its registered reads.

**Tech Stack:** Rust/Tokio, rmcp 3.2.0 client and raw JSON-RPC harness,
wiremock, assert_cmd, existing live support, xtask, Bash/jq, Podman, Claude
Code and Codex CLI as product clients.

**Spec:** [MCP design](../specs/elasticctl-mcp-design.md), especially sections
6-9; [shared conformance contract](../specs/elasticctl-design.md) section 8.3.

Status: implementation in progress. Revised 2026-09-06 after the v0.7.1 release
(tag `v0.7.1`, commit `370d082`, twenty release assets). The build matrix is
proven, so 0.7.2 needs no release candidate unless packaging changes. This
release adds no capability beyond the existing read surface. The independent
0.7.0 and 0.7.1 whole-branch reviews stand; no further review of that range
is scheduled. Fixes in this release come from defects the new tests, matrix,
or clients confirm.

## Global Constraints

- The default catalog has twenty tools; startup query opt-in adds exactly two.
- The target protocol is 2026-07-28. Also test legacy 2025-11-25 initialization through the SDK compatibility path. Live evidence must cover both paths; 0.7.0 and 0.7.1 measured only the legacy path live.
- Input line: 262,144 bytes; structured content: 262,144 bytes; complete outbound frame: 1,048,576 bytes; upstream body: 16,777,216 decoded bytes.
- Four active calls; the fifth returns `busy` immediately. Whole-call timeout defaults to 30 seconds, range 1-120. Shutdown grace is five seconds.
- The eleventh conformance contract is `mcp_reads_existing_verticals`. Its root ignored test carries the same name because the controller invokes tests by exact name.
- The MCP process sends no mutation, setup, preview, internal-user, async-query, or PIT request. Harness provisioning is separately owned and reviewed.
- The MCP transport has debug off (spec section 6), so no live request log exists. Read-only proof for live runs is the offline recording-mock route proof per tool, the child's command line and configuration, and baseline/inventory equality. The plan claims no live request capture.
- Public conformance JSON keys remain `flavor`, `version`, `contracts`, `contract`, `result`, and `error_class`. Never report a skipped or unavailable target as a pass, and never write a substitute report.
- Model-driven product clients run only against the local lab. Tool results carry `target.host`, and those clients send tool results to their model providers. Never point them at a trial deployment.
- Client configuration lives in a scratch directory outside the repository. Never create or commit `.mcp.json`, `.vscode/mcp.json`, or persistent user client settings.
- The live harness starts the `elasticctl` binary. Both binary names are proven offline in CLI `tests/mcp.rs`.
- Keep credentials, target identity, user data, raw results, and raw failures out of public evidence. Never hand-edit recorded fixtures.
- Local builds use two jobs, tests use four threads, and only one build-heavy process runs at a time.
- Keep development versions at the released 0.7.1 value; release preparation performs the coordinated bump.
