# 0.8 MCP research

Research date: 2026-11-10. Baseline: `f7c9fe5`, workspace version 0.7.4.
This is planning evidence. No 0.8 code exists. Live facts come from read-only
probes of the trial Serverless (Kibana 9.7.0) and Hosted (9.5.6) stacks; the
lab was not started and nothing was created or changed. The measured table is
in [design section 11](../specs/elasticctl-mcp-tasks-design/11-measured-behavior.md#11-measured-behavior).

## Recommendation

Add four read-only task tools over a new `elasticctl_api::compose` module,
then a small static resource and prompt surface. The `rules_list` corpus-read
fix ships first, in 0.7.5. Keep the 22 mirror tools, the 0.7 limits, and the
pinned SDK. Leave durable tasks, subscriptions, completion, and server-side
discovery out. Start the trial-dependent measurements in 0.8.0 and pass the
three-flavor matrix in every release. The
[design](../specs/elasticctl-mcp-tasks-design.md) holds the contract.

## Protocol evidence

| Evidence | Source | Consequence |
| --- | --- | --- |
| Tool, resource, and prompt lists "MUST NOT vary per-connection or as a side effect of other requests on the connection". | [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources), [prompts](https://modelcontextprotocol.io/specification/2026-07-28/server/prompts) | A catalog that grows after a discovery call is not allowed. Keep fixed lists. |
| Servers "SHOULD return tools in a deterministic order". | [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) | Keep lexical order for every list. |
| `resources/subscribe` and `resources/unsubscribe` are replaced by `subscriptions/listen`, a long-lived stream. The `subscribe` capability now means support for `resourceSubscriptions` on that stream. | [Changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog), [subscriptions](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/subscriptions) | Subscriptions need a stream and a change source. Not declared in 0.8. |
| A server with neither `listChanged` nor `subscribe` may declare `"resources": {}`. | [Resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources) | Declare empty `resources` and `prompts` objects. |
| Resource not found is JSON-RPC `-32602`; earlier revisions used `-32002`. A server must not return empty `contents` for a missing resource. | [Resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources), [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) | Return the path-correct code; never an empty array. |
| Custom URI schemes must follow RFC 3986. `https://` is only for resources the client can fetch itself. | [Resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources) | Use a custom `elasticctl://` scheme, never a Kibana URL. |
| "Resource links returned by tools are not guaranteed to appear in the results of a `resources/list` request." | [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) | Templates may address objects that are not listed. |
| `ttlMs` and `cacheScope` are required on `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`, and `resources/read`. `ttlMs: 0` means immediately stale; `private` must not be shared across authorization contexts. | [Caching](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/caching) | Keep the SDK defaults of 0 and `private`. |
| Pagination uses opaque cursors; a missing `nextCursor` ends the list; an invalid cursor should be `-32602`. | [Pagination](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/pagination) | One page per list; reject any cursor. |
| Prompts are "user-controlled". Messages may hold text, image, audio, resource links, or embedded resources. Invalid name or missing argument is `-32602`. | [Prompts](https://modelcontextprotocol.io/specification/2026-07-28/server/prompts) | Prompts are shortcuts, not a data path. Text only. |
| Completion needs the `completions` capability; an unsupported method is `-32601`; servers must rate limit and prevent disclosure through completion. | [Completion](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/completion) | Not declared. Override the SDK default so the method is refused. |
| Tasks moved out of the core into the `io.modelcontextprotocol/tasks` extension, stage "Beta, to Core". A server must never return a task to a client that did not declare the extension, and "the task must be durably created before sending the response". | [Changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog), [extensions](https://modelcontextprotocol.io/docs/extensions/overview), [tasks](https://modelcontextprotocol.io/extensions/tasks/overview) | Not in 0.8: no call outlives 120 seconds and there is no durable state. |
| The extension support matrix marks no client as supporting Tasks. The Claude Code row is empty and there is no Codex CLI row. | [Client matrix](https://modelcontextprotocol.io/extensions/client-matrix) | No evidence client is listed for Tasks or Skills. |
| "Skills over MCP" is a Beta extension that rides on resources. | [Extensions](https://modelcontextprotocol.io/docs/extensions/overview) | Not used; prompts cover the four workflows. |
| The revision defines no tool search, tool namespace, or filter on `tools/list`. | [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) | Progressive discovery is a client feature, not a protocol one. |

## Owner decisions

Recorded on 2026-11-10. Each was an open question in the first draft of
this research.

| Question | Decision |
| --- | --- |
| Ship the `rules_list` body-cap fix in 0.7.5 or only in 0.8.0? | 0.7.5. It adds `rules_ops::list_page` over `rules::find_first_by_name`: one request with `per_page=<limit>&sort_field=name&sort_order=asc`, MCP only, no schema change, CLI unchanged. 0.8.0 starts from it and adds only the `technique` and `tactic` filters. |
| Should `resources/list` read Elastic to list custom rules and open cases? | No. The list is the fixed five URIs (decision D14). |
| May the default server call Elasticsearch `_resolve/index` and return rule execution messages? | Yes, with no new flag. Each message is capped in bytes, and the design states the added disclosure in its safety section. |
| `rules_list` rows ordered by name? | Accepted. |
| Fixture directories for 9.7.0 and 9.5.6 that hold only the new operations? | Accepted. |
| Does a later 0.8 release need the three-flavor matrix? | Yes, every release, with no weakening. The live proofs are planned inside the current trial window. If it closes first, the owner supplies replacement stacks. |

## Review record

An independent review of the first draft returned eight findings on
2026-11-10, all accepted: dot segments in path values, an unbounded Fleet
collector, `no_pattern_matches` on unresolved patterns, the three-flavor gate
after 0.8.0, a latency measurement that did not reach the request maxima, the
four-request `rules_list` bound, shared-file ownership across the 0.8 and 0.9
bands, and cancel and deadline tests during a middle request. The design and
plans in this tree include the corrections.
