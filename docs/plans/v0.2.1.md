# elasticctl 0.2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the 0.2.1 compatibility patch with Windows-safe durability,
typed feature gates, normalized Hosted fallback matching, direct exception
contract coverage, and a verified 9.5.1 compatibility floor.

**Architecture:** Cache the status probe in `Transport`, express the three 0.2
feature areas as `Feature` values in `elasticctl-core`, and enforce their
verified version floor at the API route boundary without changing public API
function signatures. Keep local-only commands offline. Use the existing state
and CLI integration layers to test reports and process behavior.

**Tech Stack:** Rust 2024, Rust 1.97.1, Tokio `OnceCell`, reqwest/rustls,
wiremock, assert_cmd, serde, cargo-dist release metadata.

## Global Constraints

- Preserve dependency direction: `elasticctl-cli` → `elasticctl-api` → `elasticctl-core`.
- Preserve dry-run defaults and every existing output field.
- Do not change state-command or rule-query source defaults.
- Do not claim feature compatibility below Kibana 9.5.1 without recorded fixture proof.
- Record fixtures through `cargo xtask record`; never hand-edit fixture responses.
- Keep 0.2.2 CI expansion and package preflight work outside this patch.
- Do not tag, publish a GitHub Release, or publish to crates.io in this plan.

## File map

- `crates/elasticctl-core/src/transport.rs`: own the one-per-transport capability cache.
- `crates/elasticctl-core/src/capabilities.rs`: feature names, version floors, Hosted fallback normalization.
- `crates/elasticctl-core/src/lib.rs`: export `Feature`.
- `crates/elasticctl-core/Cargo.toml`: add direct semantic-version parsing.
- `crates/elasticctl-cli/src/context.rs`: delegate capability reads to `Transport`.
- `crates/elasticctl-api/src/exceptions.rs`: gate exception container and item routes.
- `crates/elasticctl-api/src/prebuilt.rs`: gate public prebuilt routes.
- `crates/elasticctl-api/src/rules.rs`: gate source-filtered `_find` calls only.
- `crates/elasticctl-api/src/state/transaction.rs`: open synced files with write access.
- `crates/elasticctl-cli/src/report_file.rs`: apply the same Windows-safe sync contract to reports.
- `crates/elasticctl-core/src/config.rs`: keep the Unix-only writer import Unix-only.
- `crates/elasticctl-core/tests/capabilities.rs`: test feature floors, cache behavior, and hostname normalization.
- `crates/elasticctl-api/tests/{exceptions,prebuilt,rules,state}.rs`: test gates and direct drift contracts.
- `crates/elasticctl-cli/tests/exceptions.rs`: test the missing CLI contracts.
- `crates/elasticctl-api/tests/support/mod.rs`: add only reusable complete mock responses needed by the new tests.
- `xtask/src/main.rs` and `tests/fixtures/*`: record the 9.5.1 source-partition evidence when live recording is available.
- `docs/specs/elasticctl-design.md`: make the 0.2.1 contracts normative.
- `Cargo.toml`, `Cargo.lock`, `CHANGELOG.md`: version and document the patch after behavior is verified.

- [ ] **Step 2: Make file syncing request write access**

Use this implementation in `FsFileOps` and in test adapters that perform a
real sync:

```rust
fn sync_file(&self, path: &Path) -> io::Result<()> {
```

transaction artifact disappeared, and it must never alter its bytes.

- [ ] **Step 3: Implement feature floors**

Add `semver = "1.0.28"` as a workspace dependency and consume it from
`elasticctl-core`. Implement the public enum and labels:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Feature {
    ExceptionLists,
    PrebuiltRules,
    RuleSourceScoping,
}

impl Feature {
    fn label(self) -> &'static str {
        match self {
            Self::ExceptionLists => "exception lists",
            Self::PrebuiltRules => "prebuilt rules",
            Self::RuleSourceScoping => "rule source scoping",
        }
    }
}
```

Parse `Capabilities::version` with `semver::Version`. All three variants have
the literal verified floor `Version::new(9, 5, 1)`. An invalid version is
unsupported and its original text remains in the error.

- [ ] **Step 4: Cache the probe in `Transport`**

Add `capabilities: tokio::sync::OnceCell<Capabilities>` to `Transport`,
initialize it with `OnceCell::new()`, and implement:

```rust
pub async fn capabilities(&self) -> Result<&Capabilities> {
    self.capabilities
        .get_or_try_init(|| Capabilities::probe(self, self.kibana_url()))
        .await
}

pub async fn require_feature(&self, feature: Feature) -> Result<()> {
    self.capabilities().await?.require_feature(feature)
}
```

Change CLI `Context::capabilities` to call `self.transport().await?.capabilities().await`.
Remove its second `OnceCell<Capabilities>` field.
